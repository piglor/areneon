# Damage-aware baselines

The `damage-aware` scripted baselines (v1, v2 over belief worlds, v3), their inputs, identity and use as opponents.

Part of the architecture documentation split out of `CLAUDE.md` (index: [README](README.md)). Ticket references such as `#1179` point to Redmine (`redmine.piglor.com/projects/areneon`), where measured figures and verdicts are recorded.

**`causes` stays out of the stored baseline counts (#1379).** `damage-aware@v5` (history declared, `probe-outcome/1`) makes the shared view note `causes` (probe runs that ended in a refusal or `history_unknown`, by cause) in the counts object, so `report().counts` carried a tenth key and `progress --damage-aware --damage-aware-version v5` failed on the closed `BaselineCounts` (`additionalProperty causes`). Decision: like `success` and `situational`, the table is a diagnostic of the builder, not a stored count; `report()` strips it (`storedCounts`), so no contract, reader, sample or record byte changes (a v5 record has the same nine counts plus `probe_refusals` above 0). The feature service still reads it from the memo.

**damage-aware@v2** (ADR-025 §4 to §6, §13, ADR-018 errata E-18.2 and E-18.3, slice 3 part 2, #1128; `showdown-bridge/src/damage-aware-actor.ts`, `-worlds.ts`, `-assumed-set.ts`, `team-dataset/src/damage-aware-worlds.ts`). The first consumer of the belief: the v1 scorer over sampled worlds, a new policy id `damage-aware@v2`; **v1 is unchanged** (its record, `baseline_config_hash` 1df63656…, identity bytes, choices and report have no new key; `damage-aware-worlds.test.ts` pins the hashes and `damage-aware-invariance.test.ts` still passes, its helpers moved to `damage-aware-invariance-support.ts`). **Contract:** a new schema version beside v1, not a minor change (ADR-008 §3: the v1 type would have had to become a union and every v1 reader would have been touched): `damage-aware-config-2.schema.json` (`DamageAwareConfigV2`, `schema_version` 2; generated TS and pydantic types, samples under `fixtures/contracts/v1/damage-aware-config-2/`). `config/baselines/damage-aware.v2.json`: `assumed_set {source: "belief", prior_hash, belief_config_hash, worlds: 8}` in place of v1's field rules, and v1's `hp_rounding`, `scoring` and `epsilon_ppm` with the same values; the prior is the committed `generator-matched` prior of `uniform-v1` and the belief config is `config/opponent-model/<format>/belief.v1.json` (`illusion`, 32 redraws, 64 assignments), both named by the SHA-256 of their JCS bytes (the composition root hashes the files it reads; `check-damage-aware-config.ts` in `make ts` requires the committed files to be the named ones). **Port:** the bridge does not import the opponent model (importer image, see Opponent sampler); `damage-aware-worlds.ts` declares `BeliefWorldsPort` structurally (`identity_hash` = `belief_identity_hash`, `prior_hash`, `belief_config_hash`, `prior_format_id`, `sample({opponent, flags, stream, n})`) and the composition root `team-dataset/src/damage-aware-worlds.ts` (`createBeliefWorlds`, `beliefWorldsFactory`; `team-dataset` now depends on `@areneon/opponent-model`, the one package that joins the model, the bridge's `createSetLegality` and the generator's `generatorSpreadSampler`) builds it: it loads the prior and belief config from `config/opponent-model/<format>/` and refuses (`BeliefWorldsError`) a file whose hash is not the record's, a prior of another format (N10), and a prior not derived from the committed `config/teams/<format>/generator.json`. The actor re-checks the port against the record at construction (prior hash, belief config hash and prior format: `DamageAwareError`, never the M-C prior after a pin bump); at run time the model's `format_mismatch`, `item_clause_unsupported` and `spread_sampler_required` (`BELIEF_DEFECTS`) are defects of the run and propagate, every other code is a fallback. **Play:** at a scored request (a move request with two or more candidates, as v1) the actor asks the port for `worlds` worlds of the opponent from the reader's opponent half and ALL flags the reader has raised in this game, on the stream SHA-256(JCS({request_hash, request_seq, player, purpose: "damage-aware-worlds/1"})) (`worldsStream`; every input is the player's own request, so v2 stays a pure function of the player's view; `epsilon_ppm` keeps its own Mulberry32 stream and is drawn before the worlds, so the world stream never depends on it), builds each opposing active's assumed set from the world's set for that roster position (`buildWorldAssumedSet`: the same `AssumedSet`, public facts win over the world as in v1: shown or lost item, revealed ability, level, Mega and stone, shown hit points; `revealed_moves` are the channel's revealed moves and the only threats, a sampled move never is) and scores every candidate exactly as v1 does (`scoreChoices` is v1's loop, unchanged); the per-game probe memo by query hash is shared across the worlds. The candidate with the best SUM over the worlds wins, the first of equal sums in canonical order (the sum orders candidates exactly as the mean does, the divisor being the same; no integer division loses information). A world that contradicts a public fact (a position the world does not bring, a set the validator refuses once the public facts are applied, another species, a revealed move missing, a Mega Evolution its forme does not explain, an ability that blocks the status the Pokemon is shown with, the probe's own verdict) is dropped and counted (`contradicted_worlds`), not repaired; with no world left the request plays the `actor-rule` candidate (`no_consistent_world`). Known limit: with an unsettled identity-hiding member and a shown position the world does not say which slot a shown Pokemon is (the disguise assignment is not in the world), so v2 reads the world's slot at the roster position and a world that does not hold the revealed moves there is dropped. **Identity (E-18.3):** the identity preimage gains `belief_identity_hash` only when the config is a v2 record (`damageAwareIdentity` refuses a belief hash without one and a v2 record without one); a policy id that names a record version (`v1`, `v2-x`) must be the version of the record the actor plays, so a v1 record cannot play as `damage-aware@v2`. **Report:** `report().belief` (v2 only) has `worlds`, `decisions`, `worlds_sampled`, `redraws`, `contradicted_worlds`, `no_consistent_world` and `refusals` by the model's code (`reader_flagged`, `disguise_assignments_exceeded`, `legality_redraws_exhausted`, ...); a refusal plays the `actor-rule` candidate, is counted there and not in `scored_decisions`, and the v1 counts (`reader_fallbacks`, `assumed_set_fallbacks`, `probe_refusals`, `unsupported_queries`) keep their meaning. Reader flags are sticky for the belief (it refuses with `reader_flagged` for the rest of a game; the request that carried the flagged line is counted in `reader_fallbacks`, the later ones in `belief.refusals`), unlike v1's per-request rule. The records that store counts (`LeagueRunRecord.baselines`, the progress records) have no field for the belief counts yet: v2's `counts` keep the nine v1 keys and the belief counts stay in the report and are not persisted in the run files (a follow-up if a run needs them stored). **KO counts (PR #203):** v2 keeps counting the KO share from the 16 rolls like v1 (decision): the probe's `ko` counts for a single hit equal that count, a defender on `ko_blockers` gets `unsupported` where the rolls still give a share, and "the mean of the v1 score" is v1's scorer unchanged, so one scorer serves both versions; moving both to the probe's counts is a new baseline version for both. **Format:** the N10 check compares the prior's format with the record's; a request carries no format, so the wiring must give the actor a record for the battle's format, as for v1. The cost figures are provisional until the section 13 head-to-head run (random-legal games are short). **Wiring:** `damageAwareSetupV2(engine, formatId, beliefWorlds)` builds the v2 setup from the committed record and the factory; `GenerationOptions.belief_worlds` / `damage_aware_v2` and `runGenerationCli(..., shardScript, beliefWorlds)` let a training config name `{actor: "damage-aware", policy_id: "damage-aware@v2"}` as a baseline opponent (no contract change; `team-dataset/scripts/play-generation.ts` passes `beliefWorldsFactory`; a plan that names it without a factory is refused, so the bridge's own `scripts/play-generation.ts` passes none, so a run config that names v2 must also name a `team_dataset`, the only case in which the Python driver starts that script). Not wired, by the ticket's scope: v2 in a training mix (an ADR-010 A4 experiment, ADR-025 §10), v2 as a progress or private-test opponent (the progress records, readers and `damage-aware-*` match ids are v1's; decided by the §13 cost gate and a separate ticket) and the teacher run. **Tests:** `showdown-bridge/test/damage-aware-v2.test.ts` (a stand-in port: construction refusals incl. N10, the world stream, the mean over worlds with a test that has teeth (the mean and the first world disagree), v2 on one world equals v1 on the same sets, every refusal and fallback counted, the status drop, flags reaching the belief, determinism, epsilon separate), `damage-aware-assumed-set.test.ts` (`buildWorldAssumedSet`), `damage-aware-worlds.test.ts`, `league-generation.test.ts` (v2 as a training opponent), and `team-dataset/test/damage-aware-worlds.test.ts` with the real model: the port and its refusals, the invariance test (equal choices AND equal probe questions at every request with an equal player channel when the opponent's unrevealed nature, Stat Points, items and moves 2 to 4 differ, a changed battle seed, a changed actor seed), the negative control (a port whose worlds are the opponent's real sets makes the probe be asked different questions at such a request; choices rarely differ because a sampled move is never a threat, so the control compares what v2 can leak through, the questions), determinism, and a training generation against `damage-aware@v2`. **Cost gate (N-H, `team-dataset/scripts/damage-aware-v2-budget.ts`):** the per-decision p99 gate (at most 5 s) holds with N = 8 and N is not lowered; v2 costs about 9 times v1 per decision (about 8 times the probe queries, with no memo saving: the worlds differ, so almost no query repeats); figures on #1128. Belief outcomes over the 40 games: 3,080 worlds sampled, 0 legality redraws, 8 worlds dropped as contradicting a public fact, and 26 refused requests (14 `reader_flagged`: the reader's flags persist for the rest of a game, 12 `evidence_has_no_support`: the belief found no world for the evidence of that request, a finding about the belief for slice 2's owner, not about this baseline), each played by the `actor-rule` candidate and counted. At a 200-game match against a learned policy with about 25 baseline decisions a game the mean decision is about 97 minutes, over the 30-minute match budget of ADR-018 section 6 and ADR-025 section 13: v2 does not fit the progress-evaluation budget on this machine, so it is not a progress opponent (it remains an experiment and head-to-head baseline, as section 13 provides).

**Damage-aware baseline inputs** (ADR-018 §3 to §5, slice 1, #943; the scorer, `ActorContext.team` and the A1 actor are slice 2). `DamageAwareConfig` (`packages/schema/contracts/v1/damage-aware-config.schema.json`, generated TS and pydantic types, samples in `fixtures/contracts/v1/damage-aware-config/`, integers only) is the reviewed assumption record, committed as `config/baselines/damage-aware.v1.json` (a new version is a new file, never an edit): the rule for every unrevealed opponent field (`item`: `none` or `fixed`; `ability` and `filler_move`: first or last in the team vocabulary's order; `nature`; a six-value `stat_points` spread), `hp_rounding` (`ceil`, `floor`, `nearest`), the `scoring` weights in ppm (`ko_weight_ppm`, `turn_order_discount_ppm`, `crit_weight_ppm`) and `epsilon_ppm` (0 for evaluation). `damage-aware-config.ts` reads it (`readDamageAwareConfig(value, vocabulary)`: the schema, then the format, the nature, a fixed item and the spread's sum against the pinned engine's `TeamVocabulary`; `damageAwareConfigHash` is the `baseline_config_hash` of the identity); `scripts/check-damage-aware-config.ts` (in `make ts` and CI) checks the committed file against the golden vocabulary, which `team-vocabulary.test.ts` holds equal to a fresh export. `damage-aware-assumed-set.ts` builds an `AssumedSet` from ONE opponent `PublicMon` of the shared reader, the vocabulary, the record and the engine: a revealed species (a forme the roster does not list falls back to its base species; a Mega Evolved Pokemon is its base forme holding the revealed stone, `mega: true`), level, gender, item, ability (only one the vocabulary lists for the species), and moves are used as revealed, the rest follows the record, and an unrevealed move is never invented: a `filler_move` is added only to a set with no placeable revealed move, listed in `filler_moves` and never a threat; a revealed move no legal set can hold (Struggle, Transform copies) is listed in `unplaceable_moves`. The set must pass the target format's `validateSet` and be the engine's canonical paste (else `AssumedSetError`). `assumedHp(percent, maxHp, rounding)` turns the shown percentage into hit points in integers (a shown percentage above 0 never becomes 0); the caller reads the maximum from the probe's `stats`. `test/damage-aware-assumed-set.test.ts` builds a set for every opponent Pokemon at every request of the committed random-corpus channels (both seats), checks each against the validator and runs the canary (nothing but revealed facts and the record's values; a negative control shows the canary flags a nature, spread, item or move taken from the real team).

**Damage-aware actor** (ADR-018 §1, §2, §4, §5, §6, slice 2, #944; `packages/showdown-bridge/src/damage-aware-actor.ts`, `-view.ts`, `-score.ts`, `-choice.ts`, `-identity.ts`). `damageAwareActor({engine, vocabulary, config, mechanics, snapshot?, data_class, commit?, seed?})` is an A1 `Actor` for ONE seat of ONE game (a second use of it, another seat or a shorter channel is a `DamageAwareError`); it needs `ActorContext.team` (a missing context or team is a `DamageAwareError`) and plays under `guardActor` with role `scripted`. At Team Preview it plays the `actor-rule` candidate. At a move request with at least two non-pending candidates it feeds the new channel lines to the shared reader (`createInterpreter`, incremental), joins each own active Pokemon of the request to its set of `ActorContext.team` (by the request's name; exact HP, status and held item from the request, boosts and Mega from the reader) and builds each opposing active's assumed set (`buildAssumedSet`, never the real team). Every candidate is the sum of its slot parts; a part is a damaging move's value per target (status moves, switches, `pass`, ally targets and a locked move without a target score 0; the request's target type picks single, every opposing active, or a random one averaged; any other type fails closed), each from ONE `damage` query (one attacker, one defender, one move, one declared field: weather, terrain, Trick Room and the four side conditions read from the reader) whose result is `damageValue` in integer ppm: the mean over the 16 no-crit rolls of `min(roll, hp) / hp` plus `ko_weight_ppm` times the share of rolls that reach the target's HP, mixed with the crit vector by the probe's exact chance times `crit_weight_ppm` (the probe gives no KO counts yet, so the share is counted from the rolls here). A spread move is the sum of its single-target values (no spread modifier and no ally damage in v1). The turn-order discount: when a foe's revealed damaging move can knock the actor out (some no-crit roll reaches its HP) one 1v1 `speed_order` query (the own Pokemon's action against that foe's first KO-capable revealed move; other actives do not enter the order) puts both actions in the order the engine gives, and a foe in a strictly earlier tie group discounts that (action, target) term, not the whole action, by `turn_order_discount_ppm`. The highest non-pending score wins, the first of equal scores in canonical order (so all-zero scores play the `actor-rule` candidate); forced switches, a lone candidate and pending-only sets are answered without scoring. A `unsupported` probe result scores 0 and is counted; a speed order the probe cannot queue (an action that queues more than a move and a Mega Evolution, as Focus Punch does) is counted as `unsupported` too and applies no discount (every other probe failure propagates); `refused` throws. A reader-flagged line among the lines fed since the previous request (per request, not sticky: a later request scores on a state that holds the flagged line verbatim, which is the reader's one known limit, an Illusion twin), an own Pokemon the reader does not show, or an `AssumedSetError` plays the `actor-rule` candidate and is counted (`reader_fallbacks`, `assumed_set_fallbacks`). `report()` gives `{policy_id: damage-aware@<commit> (v1 by default), identity, identity_hash, counts}`; the counts (`decisions`, `preview_decisions`, `scored_decisions`, `queries`, `probe_runs`, `unsupported_queries`, `reader_fallbacks`, `assumed_set_fallbacks`, `epsilon_plays`) are integers per game, and the ProgressGameRecord fields that store them are slice 4. A per-game memo of probe results by query hash saves repeated queries (a pure function of the query, so no answer changes; `probe_runs` counts the probes actually run). `damageAwareIdentity` / `damageAwareIdentityHash` is the baseline identity of ADR-018 §5: SHA-256 of the JCS of `{baseline_config_hash, mechanics_config_hash, adapter_format, reader_sha256, version_manifest}`. `epsilon_ppm` above 0 needs the seat's baseline seed and draws from the `random-legal` Mulberry32 stream (`randomBelow(1,000,000)`, a small export added to `random-legal.ts`, once per move or forced-switch request, then `randomLegal` when the draw falls under it); with 0 nothing is ever drawn (a spy test). The actor's choice is a pure function of the pin, both configs, the reader, the own channel, the own team and the candidates: `test/damage-aware-invariance.test.ts` plays seeded battle pairs against a first-legal opponent whose team differs in unrevealed fields (nature, Stat Points, rotated items, moves 2 to 4) and requires equal choices at every request with an equal player channel, shows the test has teeth with a baseline given the real team (`assume` option, different choices), repeats it for a changed battle seed and a changed actor seed, and checks two runs equal in choices, counts and identity. The test seams are `probe`, `random` and `assume` options (the defaults are the real probe, the real stream and `buildAssumedSet`). **Measured cost** (`scripts/damage-aware-budget.ts`, the random-play corpus teams against `random-legal`): every decision is well under the run's 30 s battle budget; figures on #944. ADR-018 assumes about 25 baseline decisions per game against a learned policy: at the measured mean decision that is 14 minutes for a 200-game match, and 29 minutes if every decision cost the 95th percentile, against the proposed 30 minutes (so the budget holds with little margin in the pessimistic reading; the owner confirms or changes it).

**Choice location of a foe, and `damage-aware@v3`** (#1180). The pinned engine's `Pokemon.getAtLoc(L)` returns `foeSide.active[L - 1]`: in a choice `move N L`, location 1 is the foe in active slot 0 (`p2a`, the reader's slot `a`) and 2 the foe in slot 1. `damage-aware-view.ts` `foesOf` numbered them the other way (`loc: letters.length - position`), so `damage-aware@v1` and `@v2` score a single-target move part against the foe the engine will NOT hit (spread and random-target moves use every foe and are unaffected). **Known limitation of v1 and v2, kept bug-for-bug** (their records, identities, choices and every past result, `teacher-h1-001` and #1131's head to head included, stand as they were; the view's `engine_targets` option is absent for them). The convention is held to the engine by `test/damage-aware-target-convention.test.ts`: a scenario battle on the pinned engine (`getAtLoc` and a played `move 1 2` that damages the slot-b foe), `foesOf` under both numberings, a feature row keyed `target: L` against the foe in slot L - 1, and v3 against v1 on seeded requests. **Fixed:** the `probe-damage/1` feature builder always uses the engine's numbering (`engine_targets: true`; nothing persisted used the rows, so the feature set id and preimage stay). **New baseline version:** `config/baselines/damage-aware.v3.json` is v1's values plus `target_convention: "engine"`, a new optional field of the `DamageAwareConfig` v1 schema (a minor change within v1: absent keeps v1's bytes and `baseline_config_hash`; an older reader refuses such a record; a new schema version was not needed because every other shape is v1's). A record that says `engine` plays as `damage-aware@v3` (the actor ties the policy id to the record: a v3 record cannot play as `v1`, nor a v1 record as `v3`), has its own `baseline_config_hash` and identity, and `check-damage-aware-config.ts` requires it to equal v1 in every value but the field and v1 to lack the field. `damageAwareSetup(engine, format, "v3")` and the scripted head-to-head (`--arm-a damage-aware@v3`, `SCRIPTED_POLICY_IDS`, `ARMS`) take it; `damage-aware@v2` still has the legacy numbering (a v2 with the engine's numbering would be a new belief record version: not built). Bench `rows_digest` before and after the fix: see #1180. **Scripted head to head, v3 against v1** (#1130 harness, 100 pairs both seats on an evaluation-only dataset, descriptive and not the Training gate): v3 beat v1 clearly (figures on #1180). The baseline's choices under the engine's numbering are better than under the reversed one on these teams; this is a baseline comparison on one dataset, nothing more.

**`damage-aware@v4`: switch and Protect values** (#1329; the new scripted teacher after the pre-league check #1274 returned WAIT: the control almost never switched out of a bad matchup or Protected when threatened, and `v1`/`v3` score a switch and a status move 0). `config/baselines/damage-aware.v4.json` is v3's values plus the new optional `situational {switch_value_ppm, protect_value_ppm}` of the `DamageAwareConfig` v1 schema (a minor change within v1: absent keeps v1's, v3's bytes and hashes; an older reader refuses such a record; generated TS and pydantic types and corpus samples `damage-aware-config/valid/v4`, `invalid/situational-*`, `reader-invalid/situational-without-engine-convention`, `hashes.json` gained additions only). Reader rule: weights need `target_convention: "engine"`. A record with `situational` plays as `damage-aware@v4` (the actor ties the policy id to the record, as for v3), has `baseline_config_hash` `ad6f8aaa...` and identity gains `situational_format` (`SITUATIONAL_SCORE_FORMAT`, 1), `world_facts_format` and the `feature_set_hash` of the `probe-damage/2` set this checkout computes only for it (its choices read both), so v1, v2 and v3 identities are unchanged; `check-damage-aware-config.ts` requires v4 to equal v3 but for the weights. **Scorer** (`damage-aware-situational.ts`, `situation.ts`; everything else is v3's): at a scored move request the actor reads the request's `probe-damage/2` arrays (`candidateFeatures2` on the seat's own channel, team and candidates, one feature memo per game; it shares the actor's probe memo and counts, so a query is asked once; the nine count keys are unchanged, and `report().situational.protect_no_facts` counts Threatened slots whose Protect went unscored because the world facts were unavailable) and classifies each own active with `classifySlot`, the ONE definition of Threatened that the situational diagnostic (#1283, `situational-move-use.ts`, refactored onto the same functions with its counts unchanged) also uses: some REVEALED foe damaging move reaches its exact HP with a no-crit roll (`ohko_rolls > 0`, or `max_ppm >= 1,000,000` when the KO counts are null) and acts first (priority above 0, or 0 and the speed relation `foe_first`; a tie is not first). A `switch N` part of a Threatened slot to a bench Pokemon NO revealed foe move reaches scores `switch_value_ppm * (1,000,000 - threat share) / 1,000,000` (threat share = the largest `mean_ppm` of the foes' revealed moves into that bench Pokemon; decision where the ticket left room); a stalling move (the world facts' stall list from the pinned engine, `DamageAwareOptions.facts_data`, read once by `damageAwareSetup(..., "v4")` and `teacherContext`) by a Threatened slot scores `protect_value_ppm` unless its `protect_streak` (the world facts reader fed incrementally on the seat's own channel up to the request, as the diagnostic reads it) is 1 or more or the facts are unavailable (then 0). Everything else is v3's scorer; the sum over slot parts picks the candidate, first of equal in canonical order. A request the `/2` reading cannot be built for (`FeatureBuildError`) plays the `actor-rule` candidate and is counted (`reader_fallbacks`, `assumed_set_fallbacks`, `probe_refusals`). **Wired like v3:** `damageAwareSetup(engine, format, "v4")`, `DAMAGE_AWARE_V4_POLICY_ID` and `GenerationOptions.damage_aware_v4` (training baselines), the teacher (`--teacher damage-aware@v4`, `TEACHER_VERSIONS`), the progress evaluation (`--damage-aware-version v4`, matches `damage-aware-v4-<mode>`, Python `DAMAGE_AWARE_VERSIONS`) and the scripted head to head (`SCRIPTED_POLICY_IDS`, `ARMS`). **Weights (proposal, not calibrated here):** 1,000,000 and 600,000 ppm, of the order of one expected KO at v1's KO weight; calibration evidence comes from the experiment run (the #1283 diagnostic on scripted v4 against v3 games, counts to go on the ticket). Tests: `damage-aware-v4.test.ts` (hand-built rows for every branch of the reading and the score; actor scenes over captured corpus requests with a controlled probe: switch to a safe bench, no switch to a reached bench, Protect fresh and repeated, nothing when no slot is Threatened or the weights are 0; refusal fallbacks; invariance on equal player channels with the real probe; determinism), `damage-aware-config.test.ts`, `teacher-generation.test.ts`, `league-generation.test.ts`.

**`damage-aware@v5`: v4 scored with the engine's success chance and history-declared damage** (ADR-022 erratum E-22.5 slice H6, #1344; `damage-aware-success.ts`, the v5 paths of `damage-aware-actor.ts`, `config/baselines/damage-aware.v5.json`). v5 is v4 with every scored part multiplied by the chance that it works NOW, read from the `outcomes` array of the `probe-outcome/1` builder (`candidateFeaturesOutcome`, the `move_outcome` probe of H2 with the player's own channel history declared by the H3 declarer, `candidate-history.ts`): no second definition of an outcome. **Record:** v4's values plus the optional `success_scaling: "engine"` of `DamageAwareConfig` (a minor change within v1: v1 to v4 keep their bytes and `baseline_config_hash`, an older reader refuses such a record; reader rule: it needs `situational`; `check-damage-aware-config.ts` requires v5 to equal v4 in every other value and v4 to lack the field; generated TS and pydantic types, corpus samples `valid/v5`, `invalid/success-scaling-unknown`, `reader-invalid/success-scaling-without-situational`). A record that says it is `damage-aware@v5`, tied to the policy id both ways (a v4 record cannot play as v5 and the reverse). **Scoring (decisions where the ticket left room):** (1) the actor declares the history of the request's own channel in EVERY damage and speed-order query of the request (`DamageViewOptions.history`, a per-request declarer through `declarerOf`, a query asked before the declarer is set is a `DamageAwareError`; the turn-order discount's speed query too), so damage values are the history-declared ones (a Last Respects row scales with the faint count, a Rage Fist one with hits taken); a query that declares an unknown fact the probe cannot settle answers `unsupported` (`history_unknown`) and scores 0 as any unsupported answer. (2) A move part's value (damage, plus v4's Protect weight) is scaled by `success_ppm` (`floor(value * success / 10^6)`) of the part's row under ONE branch: the targeted foe's first revealed damaging move (a single-target part's foe by location, else the lowest location, as the builder's `aimed` foe), else the `switch` branch (also when that move's branch was cut by `max_branches`); a spread move uses the aimed foe's row (accuracy per target is not split). A switch and a pass are certain (10^6). A part with no row (a target location with no living foe) or an `unsupported` row in its branch counts as certain and is counted (`success.parts_unread`; `parts_scaled` the others). (3) v4's "a repeated stalling move scores 0" is gone: a stalling move by a Threatened slot is worth `protect_value_ppm` with no streak rule (`situationalScore` with `streaks: null`; no world facts reader runs in v5, though the stall list still comes from `facts_data`) and the engine's chance (1/3 after one use, from the declared `stall_counter`) scales it. **Fail-safe (review of #375):** an unread outcome never raises a stalling part's value: when the chosen branch has no computed row for a Threatened slot's stalling move (the history facts were refused or unsettled, so the declared `stall_counter` differs between its two ends and the answer is `history_unknown`, or the row is `unsupported`), the situational Protect value is 0, as v4's was with no facts (`success.stall_unread` counts these). A non-stalling part with no reading still counts as certain.
