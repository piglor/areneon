# Opponent model: usage priors, belief and sampler

Usage priors and weight tables, the opponent belief and its evidence, the sampler, the generator-matched and role-sets priors, and the opponent sheet block.

Part of the architecture documentation split out of `CLAUDE.md` (index: [README](README.md)). Ticket references such as `#1179` point to Redmine (`redmine.piglor.com/projects/areneon`), where measured figures and verdicts are recorded.

**Opponent usage prior and belief configuration contracts** (ADR-025 §2, §5, slice 1 part 1, #1119; `packages/schema/contracts/v1/usage-prior.schema.json` and `belief-config.schema.json`, generated TS and pydantic types, samples in `fixtures/contracts/v1/usage-prior/` and `belief-config/`; readers `packages/showdown-bridge/src/usage-prior.ts` / `belief-config.ts` and `areneon_contracts.usage_prior`; integers only, closed, no derivation or belief code yet). A `UsagePrior` names its format, `engine_data_hash` and `vocabulary_hash`, a `kind`-tagged `source` (`smogon-chaos {month, cutoff, number_of_battles, inputs[{source_id, url, retrieved_at, size, sha256}]}`, `role-sets {role_set_table_hash, fill_prior_hash}`, `generator-matched {generator_config_hash, generator_commit}`), the `derivation` limits (`script_version`, `k_items`, `k_moves`, `k_spreads`) and `species` sorted by preview species id, each with `denominator` and `formes` (each with `weight` and four lists). **Exact integer form (review finding N4, fixed here):** every list states its `denominator`, the integer total its weights are shares of (the source holds rating weights, so it is the summed list weight, never the raw count), and a share is the fraction `weight / denominator`, never ppm. `abilities`, `items` and `spreads` hold `entries` (ids sorted, spreads by nature then the six points), `residual` (mapped mass the truncation dropped, which a consumer spreads equally over the `n` options the vocabulary allows and the list does not name: share `residual / (denominator * n)`) and `unmapped` (names with no engine id, counted and never redistributed); `items` also has `no_item` (the source key `nothing`, a legal option, not unmapped); a `moves` list has `slots`, `entries` as `{id, inclusion}` (numerators over its `denominator`, the number of sets, which is the summed item weight of the forme), `empty_slots` (the source key `''`, mean empty slots per set = `empty_slots / denominator`), `residual` and `unmapped`. The readers add what the profile cannot say, against the `TeamVocabulary` the prior names by hash (a vocabulary hash, format or engine-data hash that differs is refused; the vocabulary is required): sorted and unique ids at every level (inputs by `source_id`), species and formes in the roster, forme weights summing to the species `denominator`, abilities and moves resolving against that forme's roster entry (a forme with a `required_item`, a Mega forme, may use any ability the roster lists, as its list is post-Evolution), items in the vocabulary, natures in the vocabulary and each spread within `ev_limit`, list lengths within the `derivation` limits, every list summing exactly to its denominator (a move list: inclusions plus `empty_slots`, `residual` and `unmapped` equal `slots * denominator`, and no inclusion above the denominator; a move list's denominator equals its forme's items denominator, and `empty_slots` stays below `slots * denominator`). Weights are bounded by 10^12, so TS sums stay exact. `usagePriorHash` / `usage_prior_hash` (= `prior_hash`) and `beliefConfigHash` / `belief_config_hash` are SHA-256 of the JCS bytes. `BeliefConfig` v1 is `identity_hiding_abilities` (sorted, unique, each an ability of the vocabulary), `max_legality_redraws` and `max_disguise_assignments`; no committed config file yet. `check_data_class.py` refuses a usage prior (an object with a `source` that has a `kind`, a `derivation` and a `species` list) that holds a `paste`, an `evs` key or a team-shaped object anywhere, `fixtures/` included, so the corpus holds no such sample: the readers' refusal of them is tested inline. The samples are built from the corpus's slim vocabulary (`usage-prior-samples.ts`; the numbers are invented). The derivation from Smogon data is `scripts/derive_usage_prior.py` (see the Smogon usage prior paragraph); the `role-sets` and `generator-matched` builders and the filter (#1121 and later) are not here.

**Smogon usage prior** (ADR-025 §2, slice 1 part 2, #1120; `scripts/derive_usage_prior.py`, `scripts/usage_common.py`, `config/opponent-model/<format>/usage-prior.<month>-<cutoff>.json` with its `.NOTICE.txt` and `smogon-chaos.<month>-<cutoff>.inputs.json`). A `UsagePrior` of kind `smogon-chaos`, derived offline and deterministically (Python standard library plus the contracts package for RFC 8785 and the reader; no network; the same raw files and script give the same bytes, tested). The raw `chaos` JSON, the `.txt` summary and the `leads` table are downloaded by hand (one sequential client, `robots.txt` read, a `User-Agent` naming Areneon) into the gitignored `.tmp/chaos`, never committed (Smogon states no licence; the owner accepts the aggregate-use risk, ADR-009 erratum 1 and ADR-025 erratum E-9.2; a test greps the tree for the files' hashes and the chaos keys); the input record names each by file, URL, retrieval time, size and SHA-256 and the script refuses a file that differs, and `source.inputs` repeats those facts. **ADR-020's #975 and #976 were not resolved**, so the input record format is this ticket's (the ingestion script's `robots.txt` hash is kept in it as `robots_sha256`) and `usage_common.py` holds the shared pieces (strict decimal reader that refuses duplicate keys and NaN, name table, top k, largest remainder) for #976 to import instead of copying. **Unit rule:** source numbers are read as exact decimals (`Fraction`); a list's integer denominator is its summed weight times 10^6, rounded half to even, and each weight is its exact share of it by largest remainder (ties by id), so a list adds up to its denominator exactly. A move list has `slots` = summed move weight over summed item weight (4; refused if not a whole number within 10^-6), the denominator is the forme's items denominator and the masses are shares of `slots * denominator`, with the empty-slot mass capped at `(slots - 1) * denominator` and an inclusion at the denominator. **Mapping:** a name maps by exact engine id or exact engine name; an unknown name or an id the vocabulary does not allow for that forme (an item outside the item list, an ability or move outside that forme's roster entry, a spread over the Stat Point limit or with an unknown nature) is `unmapped`, counted per kind and never remapped (since #1209 a name also maps by the engine's own id normalisation, `toID`: lower case, every non-alphanumeric dropped, looked up among the engine ids, so `Farfetch'd` finds `farfetchd` and no spelling is listed; the first record, made before, left both unmapped); `nothing` in `Items` is `no_item` and `''` in `Moves` is `empty_slots`, in neither term of the gate. Preview species and formes come from the generator-matched prior of the same vocabulary (`shows_as`, from the engine's Mega stone data): a forme's weight is its entry's summed item weight, so a Mega forme's weight is the stone-holding share, its item its stone and its abilities the post-Evolution ones; the record carries no `holder_abilities` (the consumer reads the pre-Evolution ability from the base forme's list: the approximation of B1/N-I). A source species with no chaos entry has no entry in the record, and `belief()` refuses a roster that holds one (`species_not_in_prior`); at 2026-09 cutoff 1630 that is 69 of the 300 preview species of the vocabulary (231 species, 292 formes in the record from 294 source entries). **Fallback (#1209, second record `usage-prior.2026-09-1630.v2.json`, script `usage-prior-chaos.v2`, own `.NOTICE.txt`; the first record is kept as it was, and its re-derivation is v1's, commit d0b8e9c):** `--fallback` fills every preview species with no chaos entry (67 at this month once the two apostrophe names map) from the committed `generator-matched` prior of the same vocabulary (`preview_map`), and the record says so: `source.fallback {kind: "generator-matched", prior_hash, species[]}` (new optional field of the `smogon-chaos` source, a minor change within v1; readers refuse unsorted or duplicate ids and an id that is no species of the record; the reader cannot check the copied content, the derivation script and the record tests do). A filled entry is the map's entry cut to this record's limits: items and moves keep the heaviest (ties by id) and the dropped weight goes to `residual`, which the belief expands equally over the options not named; for moves that is exactly the map's equal inclusions, for items it also gives foreign Mega Stones and other unlisted items their equal share (wider support, no invented set); spreads are the map's one 'other spread' residual, `holder_abilities` are kept. **Why this fallback and not the role-sets prior:** a species the meta never plays has no information, and the map has the widest support (every legal option has mass), while the role-sets prior gives a move outside every role no mass, so an opponent off the curated sets would be refused `evidence_has_no_support`, trading one refusal for another; keeping the refusal would also lose every roster that holds a rare species (see the numbers below). These entries carry no usage information and a consumer must not read them as Smogon data (the NOTICE and the field say so); the derivation report has `fallback_species`. **Effect on the committed corpora** (`opponent-model/test/usage-prior-corpus.test.ts`, 49 battles, 2,152 requests of both seats): under the first record 874 requests (40.6%; 40 of the 98 seat rosters, 23 species) were refused `species_not_in_prior`; under the second 0, and the Team Preview of each of those 40 rosters is answered by `belief()` (a belief over the real prior costs seconds a request, so the test runs `belief` once per roster and checks coverage for the rest). Mapping shares at 2026-09 cutoff 1630: abilities 99.9957%, items 100%, moves 99.9996%, spreads 100% (the first record: 99.88% each), leads names unmapped none, 300 species and 361 formes (292 formes before). Truncation 16 items, 24 moves, 32 spreads (spread rows: nature then the six Stat Points); the limits are in `derivation` and so in `prior_hash`. **Gate (ADR-020 P1):** at least 95% of each list kind's mass maps or no record is written (2026-09: 99.88% for every kind). **Report** (`--report`, integers only): mapping shares and detail per kind, unmapped and dropped species, **N8** from the file's own fields (`usage` sums to 5.998 per team: the counts are over the six registered, not the four brought; the raw counts sum to 6.77 per team and side, so they are not bounded by four either), **O3** (the `leads` names that map to no species, reported only), `prior_hash`; `packages/opponent-model/src/prior-deviation.ts` (`designDeviation`) runs the move model's conditional Poisson design on every forme and reports its largest gap to the stated inclusions in ppm (2026-09: median 43,448, largest 155,224). Tests: `tests/scripts/test_derive_usage_prior.py` (a hand-computed toy file of Rillaboom, Salamence with its Mega forme and a species with no id, with invented numbers: `nothing`, `''`, truncation, largest-remainder ties, a spread over the limit, a move outside the pool, the gate, the refusals), `test_usage_common.py`, `test_usage_prior_record.py` (both committed records pass the reader and the data-class guard, their hashes and inputs, the second's fallback label and that its own species equal the first's, the raw files are in no tracked file, and, where `.tmp/chaos` holds them, the second's byte-for-byte re-derivation), `showdown-bridge/test/usage-prior-committed.test.ts` (the TS reader and the hash of both) and the `smogon-chaos-fallback` corpus samples and `opponent-model/test/prior-deviation.test.ts`. A new month is a new file.

**Usage weight table** (ADR-020 §4, §6 P1, §8 E-13.4, #976; `packages/schema/contracts/v1/usage-weight-table.schema.json`, generated TS and pydantic types, samples in `fixtures/contracts/v1/usage-weight-table/`; readers `packages/showdown-bridge/src/usage-weight-table.ts` and `areneon_contracts.usage_weight_table`; derivation `scripts/derive_usage_weights.py`). `UsageWeightTable` v1 (integers only, closed) is the weight table the later usage component of the team generator will draw from; no sampler reads it yet. Per species (a roster entry of the team vocabulary the table names by hash, with the engine-data hash) it holds `usage_ppm` (share of the summed species weight, the summed item weight of its chaos entry), `w_species` and five lists in parts per million of that species' own list total: `items` (top `k_items` 16, plus `no_item_ppm`), `abilities` (no cut), `moves` (top `k_moves` 32, plus `empty_ppm`), `spreads` (top `k_spreads` 32, `{nature, stat_points}` with no `evs` key anywhere) and `teammates` (top `k_teammates` 48 among roster species, each with `ppm` and `weight`). Each list's entries, `truncated_ppm` (mapped mass the cut dropped), `unmapped_ppm` and its semantic key sum to exactly 1,000,000 (species: `usage_ppm` plus `unmapped_species_ppm`); the one exception is a species with no positive teammate weight, whose teammate list is empty with every mass 0. `w_species` and a teammate `weight` are the exact integer root `floor((ppm * 10^(6 (r - 1)))^(1/r))` with `species_root` / `teammate_root` (2 and 2, so a full share stays a million; r = 1 leaves the ppm), recomputed by both readers. `sources` lists every input file (id, URL, retrieval time, size, SHA-256, attribution, `basis` `owner-accepted-risk`, `basis_reference` `ADR-009 erratum 1`). Readers add sorted and unique ids, the sums, the roots, the top-K limits, the Stat Point limit and that every id resolves in the team vocabulary (abilities and moves against the species' own roster entry, a teammate in the roster); `usageTableHash` / `usage_table_hash` is SHA-256 of the JCS bytes. The derivation reuses `usage_common.py`, the input record of `derive_usage_prior` (`config/opponent-model/<format>/smogon-chaos.<month>-<cutoff>.inputs.json`; a file whose size or SHA-256 differs is refused) and its file verification: `PYTHONPATH=.:packages/schema/python python -m scripts.derive_usage_weights --inputs <record> --raw-dir .tmp/chaos --out config/teams/<format>/usage/<month>-<cutoff>.json [--report R.json]`. Names map by exact id, exact name or the engine's `toID`; an unmapped name or an id the vocabulary does not allow here is counted in `unmapped_ppm`, never remapped; the gate (ADR-020 P1) refuses to write a table when under 95% of any list kind's mass maps (semantic keys excluded). Decision where the ADR left room: a `Teammates` value of zero or below carries no co-occurrence and is not weight (it is counted in the report as `nonpositive_teammate_entries`); `check_data_class.py` refuses a table (an object with a string `month`, a `derivation` object, a `sources` list and a `species` list) that holds a `paste`, an `evs` key or a team-shaped object anywhere, `fixtures/` included, and a test passes every table committed under `config/teams/*/usage/` through the guards. The committed table is `config/teams/gen9championsvgc2026regmc/usage/2026-09-1630.json` (2.1 MB, 294 species, JCS bytes, `usage_table_hash`) with its attribution `2026-09-1630.NOTICE.txt`; two derivations from the recorded files were byte-identical. P1 mapping shares in ppm: abilities 999,957, items 1,000,000, moves 999,996, spreads 1,000,000, teammates 1,000,000 (gate 950,000; no unmapped species; 2,960 non-positive teammate entries were not weighted, which confirms the file holds them). Tests: `tests/scripts/test_derive_usage_weights.py` (a hand-computed toy chaos file), `tests/scripts/test_usage_weight_table_record.py` (the committed table: bytes, hash, reader, sources), `tests/contracts/test_usage_weight_table.py`, `packages/showdown-bridge/test/usage-weight-table.test.ts`, `tests/scripts/test_check_data_class.py`.

**Usage-statistics ingestion** (ADR-020 §4, §5, #975; `scripts/fetch_usage_stats.py`, run by hand, never in CI). `PYTHONPATH=.:packages/schema/python python -m scripts.fetch_usage_stats --month YYYY-MM [--cutoff 1630] [--format ...] [--out-dir .tmp/chaos]` downloads the named Smogon monthly `chaos` JSON, `.txt` summary and `leads` file with one sequential client (User-Agent `Areneon-usage-ingest/1 (+https://github.com/piglor/areneon)`), reads `robots.txt` first in the same run and stops if any URL is disallowed for the agent, retries only 429/5xx/connection errors with exponential back-off (`--retries` 3, `--backoff` 5 s, `Retry-After` honoured up to 120 s, `--delay` 5 s between files), stops at once on any other non-200 (redirects are not followed; this includes a robots.txt 4xx, which is conservative since RFC 9309 would treat it as no restrictions), refuses a robots.txt with wildcard rules (`*`, `$`) for the agent (urllib.robotparser does not implement them), caps a response at 64 MB, validates `--month` (YYYY-MM), `--cutoff` and `--format`, sends no credentials and requests nothing else. Nothing is written unless all files were fetched and checked (chaos strict JSON, summary battle count, leads table header); files are staged and linked in, undone on failure; raw files go to the gitignored `--out-dir` (never overwritten: a new month needs its own directory, since the record names the files `chaos.json`, `summary.txt`, `leads.txt`) and the input record is the #1120 format (`smogon-chaos.<month>-<cutoff>.inputs.json`, same keys, `robots_sha256` of the robots.txt read in that run, basis `owner-accepted-risk`), written as RFC 8785 bytes and never over an existing record (the committed 2026-09 record, made by hand, is kept). Source investigation (journal of #975): Pokemon Zone refuses automated clients (HTTP 403 on its pages) so it is unused and no upstream source behind it is classified; Smogon is class (a) under the owner's accepted-risk decision; user-submitted teams are excluded. Tests: `tests/scripts/test_fetch_usage_stats.py` (local fake HTTP server).

**Opponent belief** (`packages/opponent-model`, ADR-025 §1, §3, §5, §8, slice 2 parts 1, 2 and 4, #1121, #1122 and #1124; engine-free; the bridge does not depend on it yet (the planned direction is bridge → opponent-model → public-state, and `test/packaging.test.ts` checks only that the packages it depends on do not depend on it); it depends on `@areneon/public-state` and the schema types, as TYPES only, and imports no Node built-in, engine or network module: `test/packaging.test.ts`). `belief(input) -> OpponentBelief` is a pure function of the shared reader's opponent half at the request (never a fold of lines) and takes only `BeliefInput` = `{prior: UsagePrior, vocabulary (a TeamVocabulary: rule values, roster lists, items; rules.item_clause may be absent), config: BeliefConfig, opponent: PublicSide, flags: PublicFlag[]}`; the opponent's team, `OmniscientLog`, hidden verdicts, a `BattleRecord`, the own half and the seed have no field (`test/privacy.test.ts`, a type test with `@ts-expect-error` per field and a run-time check that a smuggled field changes nothing). All arithmetic is exact (`BigInt`, reduced `Ratio`s; no float, and `test/packaging.test.ts` scans the sources for `parseFloat`, `toFixed` and the `Math.floor`, `round`, `ceil`, `pow`, `sqrt` and `log` calls; other `Math` uses are not banned). **Model:** per preview slot a forme (the prior's forme weights; a Mega forme's weight is the stone-holding share; the slot's prior species is found by the reader's `base_species`, else the shown `species`), then independently given the forme an ability, an item, a spread (named entries plus one other-spread entry) and a move set, each list with its residual expanded over every option the vocabulary allows (`fields.ts`: weights scaled by the number n of residual options, unmapped mass dropped; items over the format's whole item list plus `no_item` as a named option; the stones of the species' own Mega formes are left out of a base forme's residual, and a forme whose roster entry has a `required_item` holds exactly that item). **Moves** (`moves.ts`): forced moves (inclusion at least the denominator) first, the rest by the conditional Poisson design with odds `a / (b - a)` scaled to integers by their common denominator, the elementary symmetric polynomials by exact integer DP (`elementary`, `elementaryWithout` by the exact recurrence), the count by the two-point rule on `empty_slots / denominator`, capped by the moves that can be drawn; a revealed move is conditioned on (a count below the revealed and forced moves is impossible given them; if every count is, the count is the number of revealed and forced moves, the ADR's never-below rule); the likelihood of the revealed moves multiplies the forme's weight, a move no consistent forme's pool holds (Struggle, a copied move) and every move of a Transformed Pokemon add no constraint. **Item Clause** (`item-clause.ts`): the exact subset DP over the items in order with the slots that already hold an item as the state (2^N, 64 for six; forward and backward tables give every marginal; `no_item` exempt, the slots outside the subset take their no-item weight); `rules.item_clause` absent means independent slots, 1 enforces, any other value is a `BeliefError`; `itemClause.normaliser` is the integer total on the scale in which each slot's `Cell` (forme, item, weight) weights are integers (`top-worlds.ts`, `topWorlds(belief, k)`, is the K most likely (forme, item) combinations by exact best-first search: a DIAGNOSTIC, never a consumer input). **Brought four:** B is uniform over the subsets of `picked_team_size` that hold every required Pokemon (brought, fainted or in play, or the member a shown position is assigned to, below), so P(brought) is `(picked - s) / (N - s)` for the unrequired slots and `brought.subsets` is C(N - s, picked - s) per assignment. **Evidence allowlist** (`evidence.ts`, pinned to the reader by `test/allowlist.test.ts`: every `PublicMon` key is in `EVIDENCE_FIELDS` or `IGNORED_FIELDS`, the sources read no other field, and lines outside the allowlist leave the belief unchanged): the preview species, shown forme, level and gender; `moves_revealed`; `ability` and `item` as the reader shows them; `mega` and `mega_stone`; settled. **Mega (B1):** before the Evolution a stone holder's ability comes from the base species' list (the base forme's ability shares, else uniform over the roster entry's list) and its stone counts as its item; after the reader's `detailschange` + `-mega` the forme, the stone and the Mega forme's own ability list apply; an ability the reader still shows from before the Evolution (one the base species' roster list holds) is ambiguous after it and constrains nothing; a Mega Evolution that no Mega forme of the prior with that stone explains is `forme_not_in_prior`, while a forme change in battle that is not a Mega (a broken Disguise) adds no forme constraint (`forme_unmatched:` note). Evidence the vocabulary cannot place (an item or ability outside every consistent forme's lists) adds no constraint and is listed in the slot's `constraints` (`item_skipped:`, `ability_skipped:`, `move_skipped:`); evidence a list holds with weight 0 (no residual) excludes that forme, and evidence that leaves no world is `evidence_has_no_support`. **Refusals** are `BeliefError` with a code (`BELIEF_ERROR_CODES`) and the roster position: any reader flag or phantom entry (`reader_flagged`), more disguise assignments than `BeliefConfig.max_disguise_assignments` (`disguise_assignments_exceeded`, below), another format or engine data than the vocabulary's, an Item Clause other than absent or 1, a roster outside the format's team sizes, a species with no prior entry, more settled Pokemon than the picked size, and a prior item list with no mass. `BELIEF_FORMAT` is `belief/2`. **Received items and abilities (part 4, #1124):** the shared reader flags an item or ability a Pokemon received or copied: `PublicMon.item_received` (an `-item` line with a `[from]` other than Frisk, which shows the target's own: Trick, Switcheroo, Thief, Pickpocket, Recycle, ...) and `ability_received` (an `-ability` line with `[from]` or `[of]`: Trace, Mummy, Entrainment, Skill Swap, ...); both are sticky for the Pokemon, carried by the Illusion `_settle`, and the Python reducer has no such field (the parity test strips them). `slotEvidence` reads no item (ability) of a Pokemon with the flag, so the belief stays wider and never wrong; a consumed or knocked-off item leaves the reader with no item, so it is no evidence either. `belief` checks `prior.vocabulary_hash` against `BeliefVocabulary.vocabulary_hash` (the `teamVocabularyHash` of the whole `TeamVocabulary`; a new required field) and refuses a mismatch as `format_mismatch`; the prior must have an entry for each of the six preview species. **Illusion disguise mixture (part 2, #1122; ADR-025 §3 N-B, R11; `BELIEF_FORMAT` is `belief/2`, the output shape changed).** A species hides its identity when the vocabulary roster entry of it or one of its prior formes lists an ability of `BeliefConfig.identity_hiding_abilities` (reviewed data; no species name in code); it is unsettled until its own roster entry is in play (the reader settles it at `|replace|`, moving the facts, so the belief is recomputed from the settled state). While such a member is unsettled and a position is shown, the shortcut "the shown Pokemon are in B" is off and the belief is the exact mixture over disguise assignments (`disguise.ts`): injective maps from the shown positions to {the position's own slot} ∪ {an unsettled hiding slot}, each hiding slot used at most once. Shown forme, level and gender stay with the position (they are the details the disguise shows); moves, item, ability, Transform and Mega evidence go to the assigned slot, the assigned slots are required in B, and a position assigned away holds no evidence. Under a possible disguise a revealed move that the vocabulary knows (some roster entry lists it) but no consistent forme of the slot can hold makes that attribution impossible (a move in no pool, Struggle, still adds nothing); abilities and items keep part 1's rules (a foreign ability stays a skipped note, because Trace-like effects make it legitimate). An edge (position, slot) is feasible when the slot's evidence work exists; `hasMatching` (Kuhn's augmenting paths, Hall's condition) must find a complete matching or the belief refuses `evidence_has_no_support`; `enumerate` lists the assignments in option order (the identity first when its evidence is feasible) and returns null above the cap (`disguise_assignments_exceeded`, a fixed message and no position); an assignment whose Item Clause DP is 0 is dropped (the cap counts feasible-edge assignments before that, so it is conservative). The strict-move rule applies only while the mixture is in play (the same move is skipped without an unsettled hiding member). Known limit: an assignment to a hiding slot does not weigh P(the slot holds the hiding ability); this is exact only while the hiding ability is the species' only one (Illusion's Zoroark). An assignment's integer weight is its DP normaliser on the common scale `lcm(scales) / scale` (the joint weight is normaliser / product of the slots' integerising scales; with one assignment the weight is the normaliser, as in part 1); the subset count is the same for every assignment (every assignment requires as many slots as there are shown positions), so it does not weigh them. Decision: the brought-set rule is the ADR's (B holds the assigned slot of each shown position), not the engine's stricter one (the mimicked Pokemon is also in the four), so the belief stays wider, never wrong. Output: `assignments` (each with `moved`, `weight`, `p`, `normaliser`, `required` and its full `SlotBelief`s with cells), `disguise` (`hiding`, `unsettled`, `positions`, `total`), and `slots` as `SlotMarginal`s mixed by `p` (a single assignment gives its own numbers; `constraints` are those common to all assignments); `topWorlds` ranges over all assignments and names the one each world is in. Without an unsettled hiding member (or with nothing shown) there is one assignment, the identity, and the part-1 numbers. The reader's own Illusion-twin limit still refuses (`reader_flagged`). Tests: `test/illusion.test.ts` (hand-written channels: one and two unsettled positions, the cap, Hall's condition, evidence only one member can hold, a replace that settles, a late replace with moves and an item, with worked-out weights), `test/illusion-battle.test.ts` (the committed Illusion battle, both seats, every state before and after each `|replace|`, plus a late-replace variant built from it by moving the replace past a Spite used under the disguise; the real team is read as an oracle only and the true world always has weight above zero). Not here: damage and speed evidence (slice 4). The sampler is below (part 3), the corpus tests are in the part 4 paragraph after it. `test/corpus-smoke.test.ts` runs the belief with a uniform prior at every request of three committed random-play battles (both seats).

**Engine-sent team sheet as hard evidence in the belief** (ADR-025 erratum E1, #1155; `packages/opponent-model/src/{belief,moves,sampler,evidence,error,types}.ts`, `test/sheet-evidence.test.ts`, `test/sheet-hidden.test.ts`; the open-sheet regime). The `PublicSide.sheet` the readers attach (#1150) is the one side-level field the belief now reads besides the roster (`SHEET_FIELDS` in `evidence.ts`: species, item, ability, moves, nature, gender, level; a test pins them to the reader's keys); `BeliefInput` is unchanged. **Trapping evidence of the own request (#1127; ADR-025 §3, asked by ADR-026 N-I; `packages/opponent-model/src/trapping.ts`, `packages/showdown-bridge/src/trapping-check.ts`; `BELIEF_FORMAT` is `belief/4`).** What the pinned engine shows (read from `sim/battle.ts` `endTurn` and `sim/pokemon.ts` `getMoveRequestData`; the check below decides it, no rule is written in code): the player's own request carries `trapped` and `maybeTrapped` per own active. For the LAST living own active (with a Pokemon to switch in) `trapped: true` shows only a trap that is not hidden and `maybeTrapped` shows when a foe's species lists a trapping ability; the engine's trap loop compares an ability's display name (`Shadow Tag`) with the holder's ability id (`shadowtag`), so it never skips the held slot and the flag is the SPECIES', whichever ability the foe holds. Both are skipped for a foe whose ability is not its species' own (received, suppressed, Transformed), the lower bound whenever any active foe is such, and the whole constraint under a disguise mixture. The bridge's `createTrappingCheck({engine, vocabulary, scenario_id}, {request, team, state})` answers from a scenario battle of the pinned engine (the own side as the request shows it: items, abilities, formes, fainted; both foe actives the candidate; the engine's own `endTurn`; memoised per candidate); it returns null, and a candidate shows what was observed, whenever the scenario could differ from the real battle (not a move request, a field condition, an own team that does not match, a switch-in effect of the start that changed a declared ability or item); an own active is informative only when its request says no `trapped: true` (a Mean Look, a lock or a recharge raise it of their own and the reader does not show every such volatile: the live test found 2,019 informative actives in 1,254 requests whose real foes show exactly the observed level, and with `trapped: true` admitted it found mismatches) and the reader shows it with no volatile. The world sampler takes `trapping: {scenario_id}` (off by default; `scripts/search-worlds.ts` turns it on, `--no-trapping` off) and hands the check to `WorldSamplePort.open`; the counts gain `trapping_checks` and `trapping_seen`. `damage-aware@v2`'s port does not take it (unchanged choices). **Finding.** The format's roster has one species that lists a trapping ability (Mega Gengar, Shadow Tag its only ability). The committed corpora hold few requests that show the flags: the random-play corpus none with `maybeTrapped`, and `unavailable/` and `search-fidelity/` some (a Mega Gengar foe: `trapped: true` on the earlier active, `maybeTrapped` on the last), the rest of the 129 `trapped: true` requests of #1143's `maybe_trapped` class being own causes (a recharge, a lock, a two-turn move, a trapping move or binding volatile). The bridge uses only the actives whose request says no `trapped: true`, so an earlier active's hidden-trap flag is not used (it cannot be told from an own cause without the reader showing every volatile); on the last active `maybeTrapped` is the species', so the species-public information adds nothing to the belief. The constraint therefore changes no belief on the committed corpora and no searched share or V2 rate there (`scripts/search-worlds.ts`, before and after: the random-play corpus, 345 of 1,378 decisions, generator-matched 207 searched, 1,609 valid and 983 refused worlds, 118 V2 refusals both times (the builder's `v2_request` refusals plus the redrawn `V2:-` attempts), the check run for 316 decisions; `--extra`, the `unavailable/` and `search-fidelity/` battles, 1,275 decisions every second one, 673 searched, 5,303 valid and 4,753 refused worlds, 655 V2 refusals both times, the check run for 1,113 decisions of which 2 showed `maybeTrapped`; role-sets 27 and 66 searched both times). Own state the scenario does not model is a declared limit (a type change that is not a reader volatile, a foe's Neutralizing Gas next to a trapper: latent, the roster has neither); an own Illusion holder (the scenario starts the disguise fresh) is the same kind of latent limit. **Damage evidence of isolated hits** (ADR-025 §7, §12, R8, N9, slice 4 part 1, #1132; `packages/opponent-model/src/damage.ts`, `packages/showdown-bridge/src/damage-hits.ts`, `damage-check.ts`, `hp-display.ts`; `BELIEF_FORMAT` is `belief/5`). An isolated hit (one attacker, one defender, one hit, nothing the reader cannot account for) and its shown hit points are evidence about the opponent Pokemon that took or dealt it. **Config (a minor change within v1):** `BeliefConfig.damage_evidence` is optional (absent keeps the config's bytes and hash, and the belief reads no damage): `max_checked` (candidates asked per forme and event), `shown_hp_rounding` (`floor|ceil|nearest`: how the engine's display turns hit points into the shown percentage, the FORWARD direction; ADR-018's `assumedHp` rounding is its inverse partner, `inverseRounding` in `hp-display.ts`, and `test/hp-display.test.ts` holds `shownPercent(assumedHp(p, max, inverse(rule)), max, rule) = p` for every percentage and every maximum from 100 to 800; committed `floor`, the Champions display), `non_isolating` (`moves`: a hit of one of these or one used earlier in the same turn, Helping Hand; `lasting_moves`: used earlier anywhere in the channel because they change stats the reader never shows, Guard Split, Power Split, Skill Swap; `abilities`: held or possibly held (an unrevealed Pokemon's roster abilities) by a Pokemon in play besides the two combatants, Friend Guard, Steely Spirit, Plus, Minus, Fairy Aura; `targets`: engine move target types, the spread reduction) and `unmodelled` (candidate abilities and items whose effect depends on state the probe does not declare: Analytic, Stakeout, Supreme Overlord, the HP-threshold abilities of the attacker, Metronome; such a candidate is not asked). The reader (`readBeliefConfig(value, vocabulary)`) adds sorted-and-unique lists and every id in the vocabulary; `createDamageCheck` checks the targets against the engine's moves. The committed values are `config/opponent-model/<format>/belief.damage-v1.json` (a NEW file beside `belief.v1.json`, which is untouched, so no committed record's hash moved because of the config; the Intimidate stage is NOT in the lists: the reader shows stat stages and the probe declares them). **Hits** (`extractHits(frames, ctx)`, bridge, engine-free, over the reader's frames): a `|move|` with no tags and a target, then exactly one `|-damage|` of another side with no tag and no line but `-crit`, `-supereffective`, `-resisted`, `faint`; a reason (`NotIsolated`) otherwise, or when either combatant has a volatile, a temporary forme or a suppressed ability, an opponent item or ability it received or lost, a listed move or lasting move or target or bystander ability, an unrevealed identity-hiding member of the preview (`possible_disguise`) or a field the probe cannot declare (a pseudo-weather but Trick Room, a terrain aside). **Likelihood** (`createDamageCheck({engine, vocabulary, config, mechanics, belief, data_class, cache?}, {player, lines, team, run?})`, a port the model reads structurally as `DamageCheck`): for a candidate set of the slot (a forme, ability, item, named spread) the probe's `damage` query declares the opponent candidate at the shown hit points, the player's own Pokemon from the request in force at the move line (its team set with the request's item, ability and gender) and the reader's stages, status and field; the indicator holds when SOME roll of the no-crit vector (the crit vector after a `-crit`) takes some hit-point value of the range the display rule maps the shown percentage to (`hpRange`, a scan over every value, no inverse formula) to some value of the range of the percentage after (`rollsReach`; a faint needs a roll that reaches the lowest value). An opponent ATTACKER's own shown hit points are a range too and a move or ability may read them (Eruption, Water Spout, Reversal, Blaze): its candidate is declared at both ends of the range, and if the two answers' rolls differ the candidate gets no constraint (no move or ability is named in code; test with a stand-in probe that reads the declared hit points, plus constant-answer negative controls). An own Pokemon the request in force and the team cannot name once (0 or 2+ matches) gives `null` and is counted (`own_unstated`), never a throw. A `DamageCheckCache` belongs to one seat of one game (a port of another seat refuses it). An opponent's Mega forme, an own Pokemon in a forme its set does not have (Palafin Hero), an own evolved Mega whose shown forme is not the one its request item's `megaStone` data makes of its set's species, `unsupported` and a set the validator refuses give `null`: no constraint. **Belief** (`applyDamage`, after every other evidence, off under a disguise mixture): per event and forme the `max_checked` most likely candidates by prior mass (exact integers, ties by ids) are asked, `unmodelled` ones not; the result slot always keeps a forme (`nonEmpty`, a defect otherwise); a failing candidate gets weight 0 and the belief keeps the marginals of the exact posterior over the candidate space with every unchecked candidate passing (mean field: each ability, item and named spread is reweighted by the share of the other fields' mass that passes with it, the forme keeps the passing share of its mass), so the true set keeps a positive weight. **The worlds a consumer samples from this belief are drawn from the PRODUCT of the marginals, so a world can pair an (ability, item, spread) combination that the probe ruled out: a consumer must not assume a sampled world is jointly consistent with the hits (and several events apply one after the other, each from the marginals the previous one left, so independence is re-imposed after every event).** The "other spread" entry names no nature or Stat Points and is never checked. An event whose every checked candidate is ruled out is DROPPED and counted (`damage.contradictions`, note `damage_contradiction:<role>`), never emptying the belief; `OpponentBelief.damage` has `enabled, events, applied, checked, rejected, unsupported, unchecked, contradictions`. Tests: `opponent-model/test/damage.test.ts` (hand-worked marginals, the bound and its order, unmodelled, contradiction, unchecked, off), `hidden.test.ts` (invariance with the port on, equal player channel and opponents differing in unrevealed fields: byte-identical beliefs and worlds; negative control: a port that consults the real opponent team differs), `damage-engine.test.ts` (the sweeps, narrowing of the golden battle with the real probe, soundness at sampled requests with a prior that names the real spread among decoys, a Helping Hand put into a real turn), `showdown-bridge/test/damage-hits.test.ts` (every reason and every entry of the committed config) and `hp-display.test.ts`; `showdown-bridge/test/damage-check.test.ts` (the port with a scripted probe).

**Generator-matched prior and SpreadSampler** (ADR-025 §2, §4, §10, N-G, slice 3 part 1, #1125). `showdown-bridge/src/generator-prior.ts`: `deriveGeneratorPrior({vocabulary, config, generator_commit, shows_as})` builds the `UsagePrior` of kind `generator-matched {generator_config_hash, generator_commit}` that today's synthetic opponents are drawn from, purely and in exact integers, by the proposal's rules (ADR-013 §2): species to forme uniform over the roster entries that show as the preview species (weight 1 each; `megaPreviewSpecies(engine, vocabulary, table)` is the `shows_as` map, read from the pinned engine's `megaStone` data: a Mega roster entry shows as its pre-Mega forme, an entry the stone map does not name is its own species), abilities uniform over the entry's list, items the config's `item_weights` over the vocabulary's items (`default_item_weight` otherwise, weight 0 excluded; a forme with a required item holds only it), moves `min(moves_per_set, pool)` without replacement (every pool move has inclusion k/n, the empty slots are counted, which is the conditional Poisson design with equal weights), and one "other spread" entry holding all the spread mass. **Opponent sampler** (`packages/opponent-model/src/sampler.ts`, `draw.ts`, `identity.ts`, `canonical.ts`, `sha256.ts`, `showdown-bridge/src/set-legality.ts`, ADR-025 §4, §5, slice 2 part 3, #1123). `createSampler({legality, spreads?})` returns `{sample(belief, stream), sampleWorlds(belief, stream, n)}`; `sample` takes a belief and 32 bytes and nothing else (a type test; the seed, the opponent's team, the omniscient log have no parameter), the ports are bound once when the sampler is made, and the result is `{world, redraws}`. An `OpponentWorld` has the six preview slots; each has `brought` (exactly `picked_team_size`) and, for a brought slot, a `WorldSet` (`species` the preview id, `forme` the Mega forme id for a Mega slot with its stone as `item` and the pre-Evolution ability until it has evolved, `item` or null, `ability`, `nature`, `stat_points`, sorted `moves`, `level`, `gender`, `shown` = the nickname, species, level and gender as the channel shows them, so the preview's for a Pokemon not yet seen; a level the channel does not show is `belief.sampling.level`, the rule table's adjustLevel). Draw order: the disguise assignment (by weight), the brought set (the assignment's required slots, then a uniform draw of the rest by successive uniform picks), the Item Clause backward pass over the items in id order (the state is the set of slots still open: per item the weights are "unused" and, for each open slot that can hold it, its weight times `backward[k+1]` of the remaining open slots; `clauseTables` was split out of `solveItemClause` for it; without an Item Clause every slot draws its cell alone), then per brought slot in preview order forme with its item (a cell of the item), ability, spread, moves. Moves draw the count from the model's posterior, then the open candidates one by one with the conditional Poisson design (suffix elementary symmetric polynomials, exact; forced and revealed moves are always in). All integers come from `BitStream.below(T)`: L = bitlen(T) + 64 bits read big-endian from the stream of 256-bit blocks `SHA-256(JCS({counter, purpose: "opponent-world/1", stream: <hex>}))` (counter from 0 across the whole world, leftover bits carried to the next draw), accept `n < floor(2^L / T) * T`, return `n mod T`, else read the next L bits; no float. Decisions where the ADR leaves room: a draw with one possible outcome (T = 1, or one positive weight in `choose`) reads nothing; a legality redraw drops the leftover bits and continues at the next counter (`restart`), and the whole world is drawn again; at most `max_legality_redraws` redraws (so `max + 1` worlds), then `BeliefError` `legality_redraws_exhausted`; the tables (item DP per assignment, move suffix tables) are built once per belief (`prepared`, a `WeakMap`). `sampleWorlds` gives world i the stream `SHA-256(JCS({index: i, purpose: "opponent-world-index/1", stream}))` and weight 1/n; the redraw sum is returned. `SetLegality` (`legal(set)`) is declared in opponent-model and implemented by `createSetLegality({engine, vocabulary})` in the bridge: the pinned `validateSet` on a copy, then the canonical paste round trip; a Mega slot is checked as the preview species holding the stone (an evolved Mega ability, which the base form cannot hold, is judged with each ability the species lists and the set is legal if the validator takes any of them), an id the vocabulary does not list is illegal. **Uninformative belief mode** (ADR-025 erratum E4, EXP-B1's same-shape control arm for the belief's information, #1309; `packages/opponent-model/src/uninformative.ts`, `packages/team-dataset/src/belief-features.ts`). `createBeliefFeatures({..., evidence: "none"})` builds every opponent sheet block and every `probe-damage/3` belief move inclusion from the PRIOR ALONE: the belief reads `uninformativeOpponent(opponent)`, the roster's preview species in roster order with every other field at the reader's fresh value (no name, forme, level, gender, brought or settled flag, move, item, ability, Mega, volatile, active slot or condition; phantom entries dropped), no reader flags and no trapping check, so it reads no evidence. **What is constant and what is not (by design, decided on review):** constant across a game (and across games with that roster): the sheet block and the per-roster move inclusion lists (`moveInclusions`; the memo holds one entry per roster). NOT constant: the `belief_threats` rows of `probe-damage/3` (they use the own Pokemon's state, the living active foes, the field and the filter that leaves out a foe's revealed moves) and the `/2` arrays `threats`, `speeds`, `own_priorities` and `foe_priorities` (the channel's revealed moves and own state). The arm is the control for the belief's information, not for `probe-damage/2`'s arrays, so the two arms differ only in the belief; every `(move, inclusion_ppm)` of a belief row is an entry of the constant roster lists. **Refusal parity:** the mode refuses where the informative belief refuses for a reader reason, a reader flag or a phantom (Illusion twin) roster entry (`reader_flagged`: the sheet block is the refused block of that code over the real roster, `moveInclusions` gives `{refused: "reader_flagged"}`), and nowhere else, so the refused shares of the two arms (E4's 1% validity rule) are comparable; evidence is still never read. The builder of `/3` also skips a phantom foe's belief rows and fails closed with a `DamageAwareError` when a port gives no slot for a non-phantom foe (it used to index past the list). **Identity (decision):** the mode is an identity field, not a new feature set id: `uninformativeIdentityHash(belief_identity_hash)` = SHA-256 of the JCS of `{belief_identity_hash, evidence: "none", uninformative_format: "belief-uninformative/1"}` (`UNINFORMATIVE_FORMAT`; bump it when the blank opponent is built differently) replaces the port's `identity_hash`, so `sheetFeatureSetHash` (the block's `source.hash`, feature set string still `opponent-sheet/1`) and the `probe-damage/3` hash (`belief_threats_identity_hash`) differ from the informative arm's with no schema, contract, encoder or checkpoint-format change (a new feature set id would have meant new schema enums, generated types and Python options for nothing the checkpoint reads). The informative path keeps every byte and hash (the field is absent from its context and preimage). **Registered by hash only:** a run config names the mode by naming its hash (`opponent_sheet.feature_set_hash`, or the `candidate_features` `probe-damage/3` hash); nothing else in the config says which mode it is. `sheetSetup` and `featureSetup` try the informative port first and then `BELIEF_EVIDENCE_MODES`' `"none"` (the bridge's `BeliefFeaturesFactoryContext.evidence`), take the one whose hash the config names and refuse any other, the message listing every hash tried (the informative one first); progress and private-test setups go through the same functions. **An experiment's declaration (EXP-B1) must therefore state the hash-to-mode mapping** (which `feature_set_hash` is the informative arm and which the uninformative one) beside the run configs, because a config alone does not say it. A checkpoint made for one arm cannot be read as the other's (the hash is in the config and `encoder_version`).
