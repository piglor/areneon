# Inspector and replay viewer

The training-data inspector, replay viewer, shared player-view state reader and progress-game replays.

Part of the architecture documentation split out of `CLAUDE.md` (index: [README](README.md)). Ticket references such as `#1179` point to Redmine (`redmine.piglor.com/projects/areneon`), where measured figures and verdicts are recorded.

**Training-data inspector** (`ml/areneon_ml/inspector/`, ADR-017 §4a, §4c, #922; `python -m areneon_ml.loop inspect --run-dir R [--out D]`, default `<run-dir>.inspect/`, never inside the run directory; the pages are written to a temporary sibling, flushed and renamed over the output, which may be new or an earlier inspector output and is otherwise refused; read-only on the run directory and the dataset, standard library only for the pages, Node for the pool). It writes static, linked, offline pages for a synthetic public run: `index.html`, `distributions.html` (pool against all drawn teams: generator labels, species, items, moves, abilities and Mega Stone holders, top 15 as SVG bars plus a table of every value), `drawn-g<N>.html` (the same for one generation and how often each team was drawn), `games-g<N>.html` (every planned game: seed, both teams linked, opponent kind and baseline seat, winner, turns, outcome, forfeit loser and cause, `not recorded` for a generation older than the per-game cause) and `teams-<k>.html` (the pool's teams in hash order, 500 per page, with readable sets, labels, the games that drew each and its training-game counts by opponent kind; a win share only from 10 games, no interval). The pool is rebuilt by the loop's own function: `packages/team-dataset/scripts/print-pool.ts` (`listPool` in `pool-listing.ts` over `datasetPoolDetail` in `loop-pool.ts`, which `datasetTeamPool` now wraps, or `interimPoolSource` for a run without a dataset); a Mega Stone is whatever the engine's data marks as one. `readers.py` reads `plan.json`, `generation.json` and `team-set.json` with closed key sets (an unknown or missing key is an `InspectError`; the pin is two-step: `tests/ml/inspector/test_readers.py` ties the readers' key sets to the committed fixture run, and `training-loop.python.test.ts` (which plays a fresh tiny loop with the real worker, so it runs where the Python environment exists, as in the typescript CI job) requires the fresh run's `plan.json`, `generation.json` (top level, game rows, manifest) and `team-set.json` key sets to equal the fixture's, so a loop writer change fails one of the two), `league-run.json` and `run-config.json` through the loop's own readers, and every generation's manifest is verified before it is read. `model.py` refuses on any mismatch: a plan index outside the pool, a `team-set.json` or `generation.json` team that is not what the plan draws, an Episode that is not a synthetic `cc0-synthetic` league Episode of the run, whose own team does not hash to its plan seat or whose result differs from `generation.json` (games are joined to Episodes by seed and seat; only ids and counts are read from an Episode), and a lineage named private (a name match only: the real defence is the data, since every Episode must be labelled synthetic and `cc0-synthetic` and the pool comes from the loop's own function over a verified synthetic dataset or the committed fixture teams). `page.py` holds the §4c rules: a `<meta>` CSP first in `<head>` (`default-src 'none'`, one `sha256` script, one `sha256` style, `img-src 'none'`, `base-uri 'none'`, `form-action 'none'`), HTML escaping of every data string, data in `<script type="application/json">` blocks with `<`, `>`, `&`, U+2028 and U+2029 escaped, one script of ours with no data in it that filters rows through `textContent` and properties only, links built from fixed names and hex ids. The committed fixture is `fixtures/loop/inspector-run/` (a pruned two-generation tiny loop: the binary learner states and checkpoints are not kept and its manifests are resealed; `pool.json` is the Node side's output, compared byte for byte by `packages/team-dataset/test/pool-listing.test.ts` and by `tests/ml/inspector/test_command.py`). Tests: hostile-string canary with a negative control, no remote reference and CSP on every page, a build with sockets blocked, one canonical result for the same files. Manual check of a rendered page with no network and the CSP in force: `google-chrome --headless=new --host-resolver-rules="MAP * ~NOTFOUND" --virtual-time-budget=3000 --dump-dom file://…/games-g000001.html` shows the filter box un-hidden (the hashed script ran). Replay pages, the dashboard and the progress evaluation are later slices of ADR-017.

**Replay viewer** (`packages/replay-view/web/`, the shared interpreter in `packages/public-state/src/`, `ml/areneon_ml/inspector/replay*.py`, ADR-017 §4, §4a, §4b, §4c, #915; `python -m areneon_ml.loop replay --run-dir R --generation G [--game 3,5-7] [--out D] [--engine-data F]`, default out `<run-dir>.inspect/`, no `--game` means every played game of the generation). The training-game replay is the two players' own channels side by side, read from their Episodes (joined by battle seed and seat by the inspector's own checks: the manifest, each Episode's file hash, labels, `validate("episode")`, no `|split|`, results equal to `generation.json`); a forfeited game has no Episodes and so no replay, the hidden half is never filled in, and a non-public lineage or non-synthetic Episode is refused. It writes `<out>/replays/g<NNNNNN>/game-<NNNNNN>.html` (each file atomically) and `replays/index.html`; `inspect` leaves `replays/` as it is and its games table links to the pages that exist (a relative link, "not built" otherwise). **Clean room**: `interpreter.cjs` (it lives in `packages/public-state/src/`, below) is written from this repository's fixtures, `sim/SIM-PROTOCOL.md` and the reducer's grammar; no line of any Showdown client was used. Both viewer files are `.cjs` classic scripts: Python inlines `interpreter.cjs` then `view.cjs` byte for byte as the page's ONE hashed script (`replay_page.assets()` reads the interpreter from `replay_page.INTERPRETER`), the board CSS after the inspector's as its ONE hashed style block, and each file ends with a `typeof module` guard so the tests can `require` it (the page has no `module`). Coverage counts them: `vitest.config.ts` includes `packages/replay-view/web/**/*.cjs` and the root's `packages/*/src/**` covers the interpreter, so the per-file 90% rule (lines, branches, functions, statements) applies, and one test runs the joined script in a fresh `vm` context as the page does. No bundler, no npm runtime dependency; `tsc` checkJs runs through the package's `typecheck` (`globals.d.ts` declares `ArReplay` for the view, because the typedefs make the interpreter a module to the checker). Guards are `need(ok, reason)` calls, not `if`/`return`, so a branch is counted once. The interpreter keeps the reducer's state shape (`own` / `opponent`, snake_case fields, plus `labels` for display names) and `packages/public-state/test/parity.test.ts` compares it with the Python reducer's states at every request point of the golden, random-corpus, `unavailable/` and Illusion channels (a Python child on the root `.venv`, skipped without it) and with the committed `reduced/` goldens; a line it cannot take is kept verbatim and flagged, never dropped (`flags`), and a sweep of every committed channel requires none but the one named limit: an Illusion twin shown in two positions is not reconciled (the reducer's pair tracking is not ported; `|replace|` itself is, so the real Pokemon takes the slot and the disguise is put back). The view draws an SVG board (type-coloured tokens from the species table embedded for the species the game uses, HP bars eased between states only, never changing a state; the toggle and `prefers-reduced-motion` turn the easing off), caption bar, play/pause/step/jump/speed and a view selector, a decision panel (the request's own options with the recorded choice and `source_policy_id` marked: it shows what the log and the Episode say, with no rule of its own; the candidate list is not recomputed), the own team, and the log and raw log; `#f=N` opens a frame. The two channels are kept at the same moment by matching the lines both players see. **Page security** (§4c): `page.document(..., shell=Shell(script, style, data_id))` is the one shell (CSP meta first in `<head>`, hashes of exactly those two blocks, `base-uri` and `form-action` `'none'`), all data is in one `application/json` block, the script writes text through `textContent` and builds nodes with `createElement` / `createElementNS` only (`make()` refuses `style`, `on*` and URL attributes (`href`, `src`, `xlink:href`, ...) unless a slice opts in for a tag and name with `allowUrlAttribute`, and class names made of data pass through `token()`; the SVG namespace name is built from pieces so a scan for a URL scheme in a page stays exact). Tests: `tests/ml/inspector/test_replay*.py` (refusals, the page's own structure, CSP hashes recomputed, no remote reference, hostile canary with negative controls, sockets blocked, deterministic bytes, `inspect` keeping and linking `replays/`) and `packages/replay-view/test/` (parity, every handler, hostile strings through a DOM stand-in, source scans for sinks). The headless render (a headless Chrome or Chromium with every host name unresolvable) is a manual check: `ARENEON_RENDER_TEST=1 uv run pytest tests/ml/inspector/test_replay_pages.py` (`ARENEON_RENDER_BIN` names the binary). The sprite pack, progress-game replays, re-simulation and the Showdown export are later slices.

**Shared player-view state reader** (`packages/public-state`, ADR-018 §2, ADR-017 §4b, #943; `item_received` and `ability_received` on every `PublicMon`, #1124, see the opponent belief in [opponent-model.md](opponent-model.md)). The replay interpreter moved here from `packages/replay-view/web/`, unchanged in form: `src/interpreter.cjs` is still a classic script with the `typeof module` guard, Python inlines its exact bytes (`replay_page.INTERPRETER`), and every replay page was byte-identical when it moved (#1124 added two fields to the interpreter, so the inlined script, its CSP hash and `readerSha256`, hence the damage-aware baseline identity, changed). `src/index.ts` is the typed ESM wrapper (`createRequire`): `interpretChannel(player, lines, dex?)` (player view only; the omniscient mode is not exposed), `createInterpreter`, `parseLine`, `toId`, the state types (`PublicState`, `PublicMon`, ...), `INTERPRETER_PATH` and `readerSha256()` (the reader's file hash, a part of the baseline identity of ADR-018 §5). The package is engine-free and takes no team, omniscient log or seed. The interpreter-versus-reducer parity test (`test/parity.test.ts`, with `reduce_points.py`) and the interpreter's line tests (`test/lines*.test.ts`) are owned there; `replay-view` keeps its view, security and omniscient tests and the joined-script test, and its `test/support.ts` re-exports the shared fixtures.

**Reader and facts identity bump (#1375, #1378; PR held until the league configs are frozen).** The shared reader copies the Transform target's stat stages on `-transform` (the engine's `transformInto`, as the Python reducer does since #938; a switch-out resets them as for any Pokemon), so a later capped `-unboost` no longer leaves -6..6 and flags the request. The world facts and the history facts (and the Python `history.py` twin) take a stalling move the Pokemon already succeeded with THIS turn (Instruct re-runs it; the engine prints no `-singleturn`) as a silent success counted as one more use, as the reducer does since #1377. `WORLD_FACTS_FORMAT` is `world-facts/5`, `HISTORY_FACTS_FORMAT` `history-facts/2`; the file hashes of `interpreter.cjs`, `world-facts.ts` and `history-facts.ts` moved, so `readerSha256`, `worldFactsSha256`, `historyFactsSha256` and every feature-set hash (`probe-damage/1`, `/2`, `probe-outcome/1`, the belief sets), damage-aware identity, belief identity (`config/search/rerank-1*.v1.json` and `config/preview/*/preview-solve-1.v1.json` name it and were edited in place) and search identity are new; a run config pinned to an older hash stops computing (keep-reader-hash rule: deliberate). The interpreter still does not port the reducer's Transform move-list replacement (`moves_revealed`, #938); `parity.test.ts` compares the Transform channels without that field and has a boost-after-Transform channel.

**Progress-game replays** (`ml/areneon_ml/inspector/progress_replay*.py`, `packages/replay-view/web/`, ADR-017 §3, §4, §4b, §4c, #925). `python -m areneon_ml.loop replay --progress-dir P --generation G [--match NAME] [--game K] [--run-dir R] [--out D]` writes `<D>/progress-replays/g<NNNNNN>/<match>-<k>.html` and `progress-replays/index.html` (default `D` is `<run>.inspect` for `<run>.progress`, never inside the progress directory, nor inside the run (given by `--run-dir` or the `<run>` beside a `<run>.progress` root); `--run-dir` is optional and adds the lineage check and the run-config tie of the progress record; without `--progress-dir` the command is the training-game replay and needs `--run-dir`). It reads a committed progress generation (its `manifest.json` must match its files), `progress.json` through `read_progress_record` and each stored `ProgressGameRecord` through `read_game_record` (schema, a private data class is invalid, choices among candidates, team hashes, `omniscient_log_sha256`, the seed), then ties the two: the game is named for itself, `record_hash` is in the match's `game_record_hashes`, its outcome (by seat) equals the game row's, and a played game's log ends in the recorded winner and turn count. The page is the same graphical board and controls with one OMNISCIENT view: the engine's log has both sides' exact values and has no `|request|` lines, and the page says so at the top (both sides' hidden information; never policy input; local use only; do not share or commit it). The interpreter's `omniscient` option (`interpretChannel(player, lines, dex, true)`) makes p1 `own` and p2 `opponent`, builds both rosters from `|poke|` lines, accepts exact HP on both sides (`state.omniscient` is true, winner is `p1`/`p2`/`tie`), refuses a `|request|` and a `|split|` marker (the engine's omniscient stream already carries the secret line and no marker, so one is a defect: fail closed). The mode is the page generator's, not the data's: `replay_page.assets(mode)` writes `var AR_MODE = "player"` or `"omniscient"` as the first line of the hashed script, `boot` passes it to `init` as `options.omniscient`, and a data block that claims `omniscient` on a player-view page changes nothing (a test). Decisions are placed by the log's structure (`decision_points`: Team Preview after `|teampreview`, the k-th move decision at `|turn|k`, a forced switch at that seat's replacement `|switch|` after one of its faints, else at the end of its turn; a refused choice and its retry share a place); request numbers are shown, never used to place, because they count wait requests. The decision panel shows each seat's candidate list and chosen choice, policy id and any engine refusal; the page labels the candidate seat, mode and opponent (baseline or the previous pair). `inspect` keeps `progress-replays/` as it keeps `replays/`. Version 2 games (#951): `read_progress_games` brings the other game of a both-seats pair with a selected one (`--game 2` builds games 2 and 3 when both are stored), each `ProgressGame` knows its `pair` and `twin`, and the page links to the other game of its pair (a link made from the match id and game number only), says "Pair k, game 1 of 2", names the anchor generation with the `seen, same-lineage comparison` label and the ablation's Preview variant in the seat labels; the index lists a version 2 generation by pair (it reads only the generation's `schema_version` to decide, display only). A version 1 game's page and index are byte-identical to before. Known limits: an Illusion twin is flagged as in own channels; a forfeit's log is not checked against its outcome (the harness ends it, and the committed forfeit sample's log shows turn 4 against an outcome of 3 turns, so a bound on the log's last turn does not hold); the dashboard link is not built (there is no dashboard yet), only the inspector's index when `D/index.html` exists. Tests: `tests/ml/inspector/test_progress_replay.py` (a progress root made by the real progress code with the stand-in simulator side) and `packages/replay-view/test/omniscient.test.ts` (the interpreter on the engine's own omniscient logs of the committed random battles, cross-checked with the record's winner and turns and with each player's own channel).

**Engine re-simulation of a training game** (`ml/areneon_ml/inspector/resimulate*.py`, `packages/showdown-bridge/src/resimulate.ts` and `scripts/resimulate.ts`, ADR-017 §4a, #926). `python -m areneon_ml.loop inspect --run-dir R --resimulate G:K [--out D] [--node node] [--engine-data F]` re-runs game K of generation G on the pinned engine and writes ONE page, `<D>/resimulations/g<NNNNNN>/game-<NNNNNN>.html` (default `D` is `<run>.inspect/`, never inside the run; it does not rebuild the inspector pages, and a later `inspect` keeps `resimulations/` as it keeps `replays/`). The two Episodes are read by the replay reader (`read_games`: manifest, file hashes, labels, `validate("episode")`, results equal to `generation.json`); the Node script runs `runBattle` with `replayActor` from the game's seed, both Episodes' own teams (as brought), the config's `max_turns` and both seats' recorded choices, refusals (`[Unavailable choice]`) included, and prints both players' channels, the omniscient log, the winner, the turns and each decision with the request's legal set (choices and pending flags; no `CloneJudge` verdict, `hidden_verdicts` is never emitted). `accept` takes the result only if both channels equal the stored Episode channels line for line, the winner and turns equal the `generation.json` row, the log ends in that result, and the choices the engine took (refusal text included) are the recorded decisions; any difference is an `InspectError` that names a seat and a line number and quotes no line, and nothing is written. A forfeited game has no Episodes and is refused before the engine runs; the input is read by a closed-key reader on both sides (`readResimulationInput`). The page is the omniscient view of the progress-game replays (`replay_page.assets("omniscient")`, the same board, one hashed script and style, one data block, `textContent` only) labelled "Engine re-simulation, checked against both recorded channels", with the warning that it holds both sides' hidden information (local use only; do not share or commit it); the run directory is only read (a test compares every file before and after) and the loop still never stores an omniscient log. Teams come from the Episodes, which the loop checked against `team_hashes` when it wrote them, and the byte-equal channels pin them. Tests: `tests/ml/inspector/test_resimulate.py` (a fake runner for acceptance, every tamper and the page; the real engine on all five fixture games where it is built), `packages/showdown-bridge/test/resimulate.test.ts` (an unavailable-corpus battle with refusals).
