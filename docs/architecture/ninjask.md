# Vendored native engine: the Areneon fork of Ninjask

Part of the architecture documentation split out of `CLAUDE.md` (index: [README](README.md)). Ticket references such as `#1531` point to Redmine (`redmine.piglor.com/projects/areneon`). The track is umbrella #1530.

**What it is.** `vendor/ninjask` is a git submodule, https://github.com/piglor/ninjask, the Areneon fork of Ninjask (https://github.com/dcabatin/Ninjask, MIT, Rust with PyO3: a port of Pokémon Showdown's Champions doubles battle code, about 100x to 270x faster than Showdown's JS per core in the evaluation of 2026-11-25). It is the CPU-native engine for **training play** and, later, the native feature probes. It is vendored like `vendor/pokemon-showdown`: pinned to an exact SHA, a commit that exists on the fork's `main`, `.gitmodules` url `https://github.com/piglor/ninjask.git`. The fork's version is `<upstream>+areneon.<n>` (`0.4.1+areneon.0`).

**What it is not.** The referee. Pokémon Showdown at `PINNED_SHOWDOWN_COMMIT` stays the only authority on legality and the evaluation oracle (ADR-003); the native engine is admitted only for what the differential harness (`differential.md`) proves byte-equal with it, entity by entity, and a game is played natively only if every entity of both teams is admitted. Evaluation, progress, head-to-head, private test, best-response, search, sealed and admission paths never use it: `packages/showdown-bridge/test/ninjask-pin.test.ts` fails if a shipped or evaluating source, a Dockerfile or a compose file names `vendor/ninjask`, `.tmp/ninjask` or `import ninjask` (the allow-list is one reviewed file; the backend adapter's directory joins it when it lands), with negative controls.

**Pins.** One Showdown for both engines. The fork's `refsim/SHOWDOWN_COMMIT` must equal `PINNED_SHOWDOWN_COMMIT` (`engine.ts`) and the `vendor/pokemon-showdown` gitlink; so must `refsim/PROVENANCE.json` and the fork's `Cargo.toml` metadata (`ninjask-pin.test.ts`). `PINNED_NINJASK_COMMIT` (`src/ninjask-pin.ts`) equals the `vendor/ninjask` gitlink. The fork records the hash of every format export it was built from (`refsim/PROVENANCE.json`, checked by `scripts/repin.py provenance check` in its CI); a Showdown pin bump here is a pull request in the fork first (`vendor/ninjask/docs/repin.md`), then one here that moves `vendor/pokemon-showdown`, `PINNED_SHOWDOWN_COMMIT`, `vendor/ninjask` and `PINNED_NINJASK_COMMIT` together, with the rules snapshot and golden fixtures.

**Build.** `make ninjask`: `cargo build --release --locked --features python-module` under `.tmp/ninjask/target` (the fork's `rust-toolchain.toml`, 1.97.1), then a copy: the fork's `python/ninjask` plus the library as `_core.abi3.so` under `.tmp/ninjask/python` (put it on `PYTHONPATH`). No maturin, nothing from PyPI: the `ninjask` on PyPI is upstream's, pinned to an older Showdown; the fork's Python distribution is named `ninjask-areneon` and the import name stays `ninjask`. The package is assembled by a copy, so it is in the "installed wheel" mode (no `refsim/`, no Showdown beside it) and loads no format by itself: `make ninjask` also exports the formats listed in the fork's `refsim/PROVENANCE.json` from **this repository's** `vendor/pokemon-showdown` (`make showdown` first, or `NINJASK_REFEREE=<a built checkout at the pin>`) into `.tmp/ninjask/data/format/`, and holds them to the record (`vendor/ninjask/scripts/repin.py provenance check-data`: sizes and hashes). Load them with `NINJASK_DATA=.tmp/ninjask/data` or `ninjask.dex(id, data_dir=...)`; the engine's loader refuses an export that is not from its pinned Showdown commit (`allow_unpinned` is the explicit override, never used here). The fork's `export_format.js` refuses a checkout that is not its pin. The CI job `ninjask` (45-minute limit, no credentials in its checkout) runs the tree invariants (`ninjask-tree.test.ts`) and `cargo deny --locked --all-features check` on the vendored lock (a pinned, checksummed binary: version and sha256 are bumped together, deliberately), and only then builds Showdown and the engine, requires `ninjask.SHOWDOWN_COMMIT` to equal the Showdown pin, and runs `ninjask-pin.test.ts`, all with `ARENEON_REQUIRE_NINJASK=1`. The pin, the guards and their tests are code-owned (`.github/CODEOWNERS`).

**Supply chain.** The vendored tree is third-party code; this repository executes it only as a host-side tool, never in an image, a published artifact, evaluation, sealed generation or a privileged workflow (the two publishing workflows fetch `vendor/pokemon-showdown` alone, a test holds it), and it is gated before it can be built here: `make ninjask` and the CI job `ninjask` run the invariants below (`ninjask-tree.test.ts`) and, in CI, `cargo deny`, before Showdown or the engine is built, and the assembled package is made from nothing on every build. A Cargo build runs code of its dependencies, so the stance is stated exactly (`ninjask-pin.test.ts` holds the parts that can be checked): the engine crate has **no build script** and no `unsafe` of its own, there is no `.cargo/` directory and no `[patch]`/`[replace]` section, every package of `Cargo.lock` comes from the crates.io registry with a checksum (no git or path source), the build is `--locked`, and `cargo deny` (licences, sources, advisories) passes on the lock. Its **dependency crates do run build scripts** (15 of the 32 dependency crates at the pinned lock, among them `serde`, `proc-macro2`, `pyo3` and `libc`, measured with `cargo metadata`); that is the trust placed in crates.io and the lock's checksums, so a new crate, and any bump of the lock, is a reviewed change in the fork first. The vendored `ninjask.extension` entry-point group is opt-in (`NINJASK_EXTENSION`), so no other installed distribution can replace the engine's classes, and the test asserts the assembled package ignores a declared one.

**Public teams in the tree.** The vendored tree carries real **public** player teams: `vendor/ninjask/pools/vgcpastes-regmc.txt` (the Reg M-C teams of a public tournament-team index, third-party, attributed in the fork's `NOTICE`, which this repository's `NOTICE` points to). They are not the owner's private teams (ADR-015) and not synthetic data; nothing in Areneon may read `vendor/ninjask/pools` (a test fails if a tracked source names it, in `packages/*/{src,scripts,testing,web}`, `packages/schema/python`, `ml/`, `scripts/`, `tests/`, `config/`, `services/`, `crates/`, `.github/` and the Makefile), they never enter a dataset, an Episode, a checkpoint record or a fixture, and the fork's own checks that read them (`check_reference.py --pool`) run in the fork's CI. **Sparse checkout (decision):** `make ninjask` excludes `pools/` from the submodule's working tree (`git -C vendor/ninjask sparse-checkout set --no-cone '/*' '!/pools/'`), so the files are not on disk where the engine is built from. A submodule has no per-path exclusion in `.gitmodules`, so a fresh `--recurse-submodules` clone and the CI checkouts (`submodules: true`, on an ephemeral runner) still receive the directory until `make ninjask` runs; excluding it at the source needs the fork to move `pools/` out of its main tree (a follow-up in the fork, not done here so that the vendored commit stays the reviewed fork main). The data is public and nothing reads it, so this residual is accepted.

**Gates.** The fork's own CI (fmt, clippy `-D warnings` with and without the Python features, `cargo test --locked`, `cargo deny` for licences, sources and advisories, the fingerprint, exact agreement with Showdown on thousands of seeded games, chaos teams, refused choices, the tracker) gates the commit the gitlink names. The vendored engine is not covered by this repository's line-coverage rule; like `vendor/pokemon-showdown` it is gated by the differential admission. Supply chain: MIT and the Showdown notice kept (`NOTICE`), new crates reviewed first.

**Known limits at 0.4.1+areneon.0** (the evaluation of 2026-11-25, `.tmp/engine-eval/ninjask.md`): no `move_outcome`, no forced-draw mode, no Showdown seeds in `Batch`, no wait requests, 90 Team Preview orders instead of 360, no candidate pending flags; its `Batch.observe()` is not usable (fixed 250 floats). The follow-up tickets of #1530 (N1 to N9) close these.
