# Native probe backend

The declared-state layer of the vendored Ninjask fork behind the mechanics probe's interface (`damage`, `speed_order`, `stats`): its process transport, the backend, its differential and admission, measured speed, and what it leaves to the pinned probe.

Part of the architecture documentation split out of `CLAUDE.md` (index: [README](README.md)). Ticket references such as `#1534` point to Redmine (`redmine.piglor.com/projects/areneon`), where measured figures and verdicts are recorded. The track is umbrella #1530 (ticket N3); the vendored engine is described in `ninjask.md` once its pin lands, the harness in [differential.md](differential.md) and the probe in [mechanics-probe.md](mechanics-probe.md).

**What it is for.** Training games ask the pinned probe about 40 `damage` and `speed_order` queries per decision (the `probe-damage/1` and `/2` feature rows, threats, speeds and priorities), at about 1.5 ms each: two thirds of the play time of a features run. The native probe answers the same questions from the fork's calculators (`ninjask::calc`) in microseconds, **for training games only and only for content admitted by byte-equality with the pinned probe** through the differential harness (ADR-030 rules 2, 4, 6, 7). The probe stays the definition and the evaluation path (ADR-016 as amended by ADR-030); no evaluation, progress, search, sealed or admission path imports the backend (a source scan, `packages/team-dataset/test/differential-native.test.ts`). It is not wired into any training run yet: routing in the batch seam, `generation.backends` and the per-generation shadow check are N7's (#1538).

**The declared-state layer** (fork `src/declared/`, `docs/declared.md` there). A `Prober` over a loaded format export; sets are registered once by number (`SetSpec`: names, Stat Points, level), queries mirror `MechanicsQuery` over the set numbers (`deny_unknown_fields`: a `history` block or a field of a later contract is refused as a frame, never read without it). It builds the scenario the probe builds (two Pokemon a side, a damage query's partner with no ability and no item, Showdown's scenario seed, no Team Preview) and declares the state absolute through the engine's own setters (Mega Evolution with its ability's start effects, HP, status through the `SetStatus` events, stages, weather, terrain, Trick Room and the four side conditions, then the stages and items again), runs the pre-hit steps the reference runs and the calculator does not (the abilities' `TryMove`, a move's own `onTry`/`onTryMove`/`onPrepareHit`, Protean and Libero, Psychic Terrain's block of a priority move, a target the move's `ModifyMove` changes) and reads `calc` (rolls, crit rule as the engine's own `randomChance` pair, KO counts with the mechanics config's `ko_blockers`) or the action speeds, priorities and the engine's `comparePriority` order. A draw the reference's recording random source would have seen (a Quick Claw roll, a declared sleep, a tie of equal speeds in an event sort) is `unsupported` `random_effect` at the same position. **It never guesses:** a move whose pre-hit step it does not model, a state the engine refuses and a step it cannot reproduce are an `Abstain{entity, why}` (`move:<id>`, `state:<kind>`, `query:history`), the backend returns a `NativeAbstain` outcome and the caller routes the query to the pinned probe. No game rule or id is written in the glue: the fork's tables are the pinned Showdown's export.

**Transport** (`packages/showdown-bridge/src/native-probe-process.ts`). A long-lived `ninjask-probe` child process (`--dex FORMAT_EXPORT.json --in PIPE --out PIPE`), frames `[u32 little-endian length][JSON]` over two named pipes the parent reads and writes with non-blocking `fs` calls: the batch seam's `BatchRunner` is synchronous, so the channel is too, and a hung child ends in a timeout (default two minutes), not a hung game process. A panic in the engine ends the child, never the game process: the backend abstains `native:process` for that batch, starts the process again on the next one and gives up after four consecutive deaths. A napi addon was rejected (a panic would abort the game process; a native Node module enters the supply chain); a Python process (`ninjask.Prober.serve(frame)` serves the same frames) is slower than a binary and not needed. The binary and the format export come from `ARENEON_NINJASK_PROBE` and `ARENEON_NINJASK_DATA` (the files `make ninjask` writes), so no source names a path of the vendored tree; switching to `vendor/ninjask` is a change of those two values.

**The backend** (`native-probe-backend.ts`, `native-probe-wire.ts`). `nativeProbeBackend(engine, {config, command, backend_commit})` is a level-1 `Backend` of the harness (`id`, `backend_format` `NATIVE_PROBE_FORMAT`, `backend_commit` the fork's commit, `run(batch)`): the result's envelope (identity, set check, scope check, scenario check) is the probe's own (`probeEnvelope`), only the `answer` of a `damage`, `speed_order` or `stats` query is native, so a result differs from the probe's in no byte but what was computed. It sends only sets the pinned validator accepted, in the engine's names; a set the native dex does not know abstains `state:set`; `move_outcome` abstains `kind:move_outcome` (N4). `counts` reports answered, `unsupported` and abstained by entity (the per-entity fallbacks run metrics will report) and the milliseconds in the envelope and in the transport and native layer.

**Differential and admission** (`packages/team-dataset/src/differential-native.ts`, `scripts/differential-native-admission.ts`). Only ANSWERED queries are compared and tallied (an abstained query routes to the probe and is no evidence either way); coverage is counted beside the tally. Corpora: the committed random, search-fidelity and unavailable corpora as the `probe-damage/2` builder issues them (regression); the **move sweep** (every damaging move of the roster, one or two users, three defenders, ten states: plain, both terrains that read a move, sun, rain, one and two screens, Aurora Veil, a sleeping user, Trick Room), the **speed sweep** (seeded random `speed_order` queries over validator-checked sets: every ability and item, statuses, stages, HP, fields, Trick Room, Tailwind, priority moves, switches, declared and chosen Mega Evolution), the damage kernel's interaction sweep and its targeted corpus; and the fresh corpus (battles of the generator pool drawn from the backend version's fresh seed, ADR-030 rule 7). `differential-native-admission.ts fresh|ledger` follow the kernel's flow (shards in battle order, the ledger in its lines form); `bench` times the probe, a single native call and a batch of 256 on the same queries. `native-probe-cases.ts` writes the fork's test fixture (`tests/fixtures/declared/cases.jsonl`: each case a query in the layer's form with the probe's answer, refusing to write a case the layer answers differently).

**Classes found by the differential (each a regression case in the fork's fixture):** Protean and Libero (the engine's prepare-hit type change, which the read-only calculator does not run); a weather's forme or type change (Forecast, Mimicry, Flower Gift: the engine's setters, clear-then-set on the damage path only; the speed path sets without clearing, and a weather already up is not set again: no event, no draw); a priority move under Psychic Terrain (the dex priority, not the queue's modified one); Armor Tail, Queenly Majesty, Dazzling and Damp (the engine's `TryMove` event with the dex priority; `unsupported query_kind`); the crit vector of a crit-immune defender (the no-crit vector) and the crit rule as the engine's own pair (stage 4 is `1/1`); Expanding Force in Psychic Terrain (the target is drawn again: `random_effect`); tie draws in the event sorts the calculator skips; Beat Up (multi-hit by its `ModifyMove`); charge moves (a stop unless instant in their weather, Electro Shot raising Special Attack first); a move's own `onTryHit` runs inside the hit loop the probe replaces (Brick Break does not break screens in the probe; two screens make the damage events tie: `random_effect`); Magician's after-move sort of two equal-speed targets; one Mega Evolution a side.

## Results (vendored fork commit 18da58a5, pinned Showdown 7244fe8e)

The vendored gitlink, `PINNED_NINJASK_COMMIT` and the ledger's `backend_commit` are one commit; `packages/team-dataset/test/native-ledger-commit.test.ts` runs always (no build) and fails when the committed ledger names another commit than `git ls-tree HEAD vendor/ninjask`. A bump of the gitlink therefore needs a new fresh corpus and ledger (`differential-native-admission.ts fresh`, then `ledger`; the fresh draw's seed derives from the commit).

**Differential.** Native against the TypeScript probe, byte-equal `MechanicsResult` JCS bytes where the native layer answers.

"200,000 distinct" is the size cap of the fresh corpus (`--size`): the ledger takes the first 200,000 distinct answered queries in battle order. "Issued" counts the queries the builder asked, deduplicated within each shard by query hash (the run used one shard), so it is not a count of every call.

Ledger: 1,275 entities listed, 1,018 admitted; 134,668 pairs listed, 99,711 admitted; 0 revoked. Admission hash 43bf059b... Tier: provisional (one fresh corpus of about 213k queries from 323 battles). The ledger contract has no tier, battles or audits fields yet (ADR-031 E5 part h, #1544), so the battle count is recorded here.

**Classes found by the differential, all layer bugs, each with a regression case in the fork's `tests/declared.rs`:** Mega Sol (67 in search-fidelity: the layer did not set the move's current user), Fickle Beam against an immune defender (13 in an earlier fresh draw: the power draw is never reached), and two Damp holders of equal speed (4: the TryMove sort ties and draws). The fresh draw against the first layer commit found the latter two; the corpus above is a new draw against the fixed commit.

**Abstentions** (explained interface differences, routed to the TS probe through an unadmitted ledger entity): `move:counter`, `move:focuspunch`, `move:mirrorcoat`, `move:chillyreception`, `move:shellsidearm`, `move:aurawheel`, `state:fractional_priority`, and declared sleep or tie-draw states (`state:status:slp`, and brn, frz, tox, par, psn in the speed sweep). The report lists the top 25 per corpus.

**CI.** The `ninjask` job builds `ninjask-probe` with the module (`make ninjask`), exports `ARENEON_NINJASK_PROBE` and `ARENEON_NINJASK_DATA`, and runs `native-probe-backend.test.ts` and `differential-native.test.ts` with `ARENEON_REQUIRE_NINJASK=1`, so an absent build fails there. The bound: the tests run the committed corpora, the sweeps, the negative controls and the fixtures (about 13 seconds), not the fresh corpus (about 25 minutes), which is regenerated offline and tied to the vendored commit by the always-run ledger test.

**Speed.** Non-idle machine: i7-14700KF, 28 logical CPUs, load average 4.4 to 5.5 from the training queue; release build with debuginfo; one process at a time. `differential-native-admission.ts bench` over 3,000 builder queries (2,952 answered, 0 differing); it times the TS probe on the same queries, with no warm-up pass and the first call of each path included, so the figures carry that bias.

| Path | median | p99 | mean |
|---|---|---|---|
| native through the boundary, single call | 80 us | 246 us | 91 us |
| native through the boundary, batch of 256 | | | 61 us per query |
| TypeScript probe | 1,833 us | 4,138 us | 1,608 us |

Counters of the bench run (10,986 answered): envelope 699 ms (64 us per query: the probe's own schema validation, set check and hashing), transport plus native layer 604 ms (55 us per query, including frame encoding and the pipe; the native calculator alone is not timed separately).

**Feature builder, `probe-damage/2`, per decision** (`packages/team-dataset/scripts/builder-cost.ts ts|native [BATTLES]`: 10 random-corpus battles, 386 decisions, 18.5 queries per decision, one memo per game and seat, one query at a time; a query the native layer abstains on is answered by the TS probe; load 4.4 to 4.8; each mode run twice in both orders, within 2%, no warm-up pass):

| | per decision | answering queries | builder's own code |
|---|---|---|---|
| TS probe | 32.5 ms | 29.1 ms | 3.3 ms |
| native backend | 5.2 ms | 2.4 ms | 2.8 ms |

The split of the builder's own 2.8 ms comes from `node --cpu-prof` over 40 battles (1,608 decisions): inclusive times, nested, so they do not add up, and the sampling attribution is approximate. Query envelope (`probeEnvelope`: `canonicalJson` 0.86 ms, `readMechanicsQuery` 0.31 ms) about 1.0 ms; pipe round trip 0.9 ms; reader and request opening 0.58 ms; assumed-set construction (`buildAssumedSet`, containing the validator's `validateSet`) 0.36 ms; `featureSetIdentity` hashing 0.36 ms; declared-set memo 0.29 ms. With native answering, what remains is mostly Areneon-authored code, so the next cost is the envelope and the builder, not the engine. A lean envelope in the native backend would remove about 1 ms per decision. Row construction was not isolated as a separate figure.

**Not verified:** the byte-equality claim covers only queries the layer answers, so a query it answers and the probe never would is not seen by the differential.
