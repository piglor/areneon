# Search distillation

Search labellers, the label stream contracts and distillation in the learner.

Part of the architecture documentation split out of `CLAUDE.md` (index: [README](README.md)). Ticket references such as `#1179` point to Redmine (`redmine.piglor.com/projects/areneon`), where measured figures and verdicts are recorded.

**Search label stream contracts** (ADR-026 erratum E2 decision 4, SD-c, #1288; contracts and readers only: writing labels is SD-d, reading them in the learner SD-e). Search labels travel in a separate hashed label stream (`labels.jsonl` with its manifest `label-set.json`), never in an Episode, a `PolicyQuery` or the PPO stream, whose bytes and hashes are untouched. `TrainingExample` gains the optional closed `search_target {prior_ppm: [int], entries: [{candidate, q_ppm}]}` and `TrainingSet` the optional `search_labels {search_identity_hash, labelled, refused: [{reason, count}]}` (minor changes within v1, integers only; a writer omits them, so every existing sample keeps its digest; generated TS and pydantic types, samples `training-example/*search-target*` and `training-set/*search-labels*`). The search identity is stream level, in the manifest block only. Schema: `entries` 2 to 16 (`k_max`), `candidate` and `prior_ppm` bounded by the 1,024 candidate cap, `q_ppm` and each prior entry 0..10^6, `refused` counts at least 1, reasons `[a-z][a-z0-9_]*`. Reader rules, TS (`readTrainingExample` via `searchTargetProblem`, `readTrainingSet`) and Python (`StreamChecker`, `read_stream`, `check_stream_file`): the example carries `candidates`; `prior_ppm` has exactly one entry per candidate; `entries` ascending by candidate index, unique, in range, every one non-pending, their `prior_ppm` summing to at least 1 (the completed-Q weighting divides by it), at most `SEARCH_K_MAX` (16, also a reader rule beside the schema's `maxItems`); the manifest's `labelled` equals `examples` and `refused` is sorted by reason and unique; and, at stream level (Python, which sees the lines), `search_target` is on every line or on none and the manifest has `search_labels` exactly when the lines do. `learner_ready` stays independent. The parallel loader needs no new header field: the `labels:` class (`y` or empty) rides in `StreamChecker.classes` like the feature set and sheet source, so pieces join and `finish` refuses a mix (`test_parallel.py`). The hash tie to the stream is the manifest's existing `stream_sha256` and `examples`; checking that a label stream's identity equals the run's label config is the learner's (SD-e). Tests: `tests/contracts/test_training_labels.py`, `packages/showdown-bridge/test/training-label-contracts.test.ts`, `samples.test.ts` (the reader-invalid list and messages).

**Search distillation in the learner** (ADR-026 erratum E2 decisions 5 and 8, ADR-010 erratum A10, SD-e, #1291; `ml/areneon_ml/learner/{config,labels,ppo,trainer}.py`, `loop/driver.py`; reading labels only, the labeller is SD-d). `TrainingRunConfig` gains the optional `generation.search_labels {search_config_hash, label_share_ppm, start_generation}` and `ppo.search_distill {coef_micro, c_scale_micro, min_spread_ppm, aggregate_generations}` (minor changes within v1; absent keeps every byte, report and hash; generated TS and pydantic types, samples `training-run-config/*search-distill*`). Reader rules, TS `readTrainingRunConfig` (`checkSearchDistillation`) and Python `read_run_config` (`_check_search_distillation`): both blocks or neither; `warm_start` and `ppo.value_warmup` present and `start_generation` at least `value_warmup.generations` + 1; no `opponent_sheet`; no candidate feature set outside `VALUE_FREE_FEATURE_SETS` (`probe-damage/1`, `probe-damage-belief/1`; `/2` and `/3` pool rows into the tokens the value reads; the two lists are held equal by a test); a `team_dataset`; no `population` (the population driver has no per-member labels); the schema holds `label_share_ppm` 1..10^6 and `aggregate_generations` >= 1. **Target** (`labels.py` `distill_target`, float64 and `math`, from the stored label alone): z = ln(max(prior_ppm, 1) / 10^6); q-hat = q for a searched candidate and the prior_ppm-weighted mean of the searched q for every other one (pending included; the root value is not used); x = min-max of q-hat over the searched set; no target when q_max - q_min is below `min_spread_ppm` or zero (counted in `LabelSet.below_spread`); pi' = softmax(z / tau + c_scale * x) over every candidate, tau the run's play temperature, truncation ignored. **Loss** (`ppo.distill_kl`, `Learner._minibatch_loss`): lambda times the mean over the minibatch's labelled steps of KL(pi' || pi_theta) at tau over the real candidates, a second Battle forward pass on the label queries; Battle role only, off during the value warm-up; under `shared_trunk` its gradient reaches the trunk as the anchor's does. The usable labels are shuffled by a generator of their own (seeded from the learner seed, the update index and the epoch, so no state to store and the main generator is untouched: a run without the block and the Preview role keep their orders) and spread over the Battle minibatches with `Learner._spread`: with few labels only the first minibatches carry the term, and with aggregation a label batch can exceed `minibatch_size`. Cost: the N aggregated streams are re-read and re-encoded every generation, so the label load cost scales N-fold with `aggregate_generations`. `Learner.train(trajectories, labels)` takes `labels` exactly when the config has the block (an empty list before the first label stream). **Reading** (`LabelReader`, its own path; the PPO path `_ready` still refuses `search_labels`): each label stream through `check_stream_file` with its manifest, `search_identity_hash` equal to the one that stream's OWN generation's `generation.json` states (`search_labels {search_config_hash, search_identity_hash}`, which the labeller writes with the generation's label counts, and whose config hash must equal the run config's; the inspector's closed `generation.json` key set needs that key then); an older generation's manifest is verified (`layout.verify_generation`) before its label files are read, so a tampered older stream is a `RunDirError`, `learner_ready`, played by the pair of that generation (`league-run.json` for an older one), a Battle decision, no decision labelled twice; the driver reads `labels.jsonl` and `label-set.json` of the current and the previous `aggregate_generations` - 1 generations from `start_generation` (a generation that labelled has both files and a generation that labelled nothing has none, never an empty stream: the contract holds at least one example; the block in `generation.json` carries the counts that tell the two apart, and a missing file of a labelled generation, or files beside a count of 0, is a `LoopError`). **Reports:** the Battle role of `train-report.json` gains `search_labels`, `search_kl_before` and `search_kl_after` only with the block (the dashboard reader `read_train_report` takes the three together on the Battle role, a count and non-negative finite KLs); `learner bench` refuses a config with the block; the learner-state sidecar already holds the `ppo` block. **Provenance:** the generation manifest gains `label_set_hashes` (only with a label stream), each checkpoint record lists the label sets it read with the PPO set in `training_set_hashes` (sorted, unique; `_record_sets`, checked on resume), and `sources_registry` maps each `label-set.json` hash to the pair that played it. Tests: `tests/ml/learner/test_search_distill.py` (target and KL worked by hand on three candidates with a pending one, a zero prior and a below-spread label, at tau 1 and 0.5; the reader; report keys; absent block equal to plain PPO; the shared trunk), `tests/ml/loop/test_search_distill.py` (a tiny loop with fake labels: report, records, registry, provenance export, byte-identical rerun, kills at four stages), `packages/showdown-bridge/test/training-run-config.test.ts`, `samples.test.ts`. Not here: EXP-SD1 (the labeller is the next paragraph).

**Search labellers and the label stream** (ADR-026 erratum E2 decisions 1 and 3 to 6, SD-d, #1290; `packages/showdown-bridge/src/search-labeller.ts`, `league-generation.ts` `labelSetup`, `generation-cli.ts`, `packages/team-dataset/src/progress-search-setup.ts`). After a game, off the play path, a hashed share of the pair's own Battle move decisions is labelled by the search from the STORED Episode alone, and the labels go to `labels.jsonl` with `label-set.json` in the generation directory. Nothing searched is played or enters an Episode or the PPO stream (a labelled generation's `stream.jsonl` is byte-identical to an unlabelled one's); a run without `generation.search_labels`, and every generation before `start_generation`, writes the bytes it always did. **Setup:** `labelSetup(engine, config, pair, factory, features?)` reads `generation.search_labels` and `ppo.search_distill.min_spread_ppm`, loads `config/search/rerank-1-label.v1.json` (`LABEL_CONFIG_NAME`), refuses (`GenerationError`, exit 1) a config whose `search_config_hash` is not that file's hash or a script with no `SearchSetupFactory` (the bridge does not import the opponent model: `team-dataset/scripts/play-generation.ts` passes `progressSearchSetup`, which now takes the config), and joins the search setup, the pair's checkpoint ids, the version manifest, the run's `generation.play` and the feature configs. **Selection:** `labelSelected` (a Battle MOVE request, two or more non-pending candidates, the first 8 bytes of SHA-256 over the JCS of `{run_key, generation, game, player, request_seq, purpose: "search-label/1"}` as n, selected when `n * 10^6 < share * 2^64`, exact integers; vectors computed with Python hashlib). **Labelling** (`labelEpisode(context, episode, hash, game)`): the Episode is read through `readEpisode` (inside `readTraining`; the stored file must hash to its name), its collection seed must be what `league-seed/1` gives for this run, generation and game (`LabelError` otherwise), each selected decision is cut with `decisionObservations` (the own channel up to the request), the prior is the worker's `evaluate` on that observation (with the root query's candidate features for a pair that reads `probe-damage/1`), the world request is `worldRequestOf` (extracted from `searchActor`, which calls it too), the stream is `searchStream({seed, game, player, policy_id, request_seq})` under the SEARCH policy id (`labelPolicy`: `searchPolicy(setup, manifest, pair, "sample", play, features)`), and `searchLabel` of a `searchActor` built for the Episode gives the entries. `LabelContext` has no field for a `BattleRecord`, an omniscient log, hidden verdicts, the seed or the opponent's team (type test). **Refusals** (counted, `LABEL_REFUSALS`, sorted): `belief_refused`, `below_min_valid` (fewer than W_min worlds), `world_dropped` (any world dropped by the reply model or the engine in that decision), `spread_below_min` (q spread under `max(1, min_spread_ppm)`), `too_few_searched` (under two searched candidates), `no_prior_mass` (the searched candidates' prior under 1 ppm) and `features_refused`. **Files:** each game process labels the Episodes it wrote when its games are done (`writeLabelFiles` at the end of `playEntries`, the way #1185's feature rows are recomputed; `--labels-dir` is the internal scratch directory of the shard scratch, or a temp directory of a lone process) and leaves `<episode hash>.search.json` (JCS: the decisions with their prior and entries or their refusal, and the decision's evidence class, a diagnostic only). `playGeneration` then writes the stream (`writeLabelStream`): Episodes in hash order, decisions in request order, each the Episode's own `TrainingExample` (`examplesOf` with `only`, rows from the #1185 sidecar when there) plus `search_target {prior_ppm, entries}`; a missing or stale file (wrong format, hash or search identity) is recomputed by the writer's process, and more than 5% missing is a `LabelError` (a `GenerationError`: a harness incident). A game process whose labeller throws leaves no file and a stderr line naming the game and the error class (never content); the writer recomputes it and fails the generation if that fails too, so a failure is counted and loud, never a forfeit and never skipped. `generation.json` gains `search_labels {search_config_hash, search_identity_hash, selected, labelled, refused[{reason, count}], recomputed}` for every generation at or after `start_generation` (counts only, no diagnostic classes; `labelled + sum(refused) = selected`; read by `loop/label_counts.py` in the inspector and the driver, which refuses files beside `labelled` 0, a missing file beside `labelled` above 0 and a count other than the manifest's; the generation CLI prints the same counts on stderr as `search labels: {...}`; `labelled` 0 does not stop a run, the counts make it visible), and `label-set.json` (a `TrainingSet` with `search_labels {search_identity_hash, labelled, refused}`; `episode_hashes` are the Episodes that carry a label) exists when at least one decision was labelled. **A generation with no label writes no label files** (the schema holds `labelled` and `examples` at least 1); its block says `labelled` 0, and the driver reads it as zero labels. `world_dropped` refusals skew the labels toward states where the reply model never fails in any sampled world, which the counts show. **Deviations from the ticket text, decided here:** (1) no separate `--label-processes`: each game process labels its own Episodes with the worker it already has (the prompt's #1185 pattern; labelling runs after all of the process's games, never beside them), so there is no extra worker, no `nice` (a raised niceness would slow the process's remaining merge too) and no hand-off of paths; (2) the #1283 situational classes need `probe-damage/2` rows, so the diagnostic class is `evidenceClass` (maybe_trapped, volatile, timed_condition, unseen_brought, rest), counted per label and refusal in `LabelTotals.classes`, not stored in any run file; (3) `playGeneration` needs `episodes_dir`, `stream_path`, `labels_dir` and `labels_path` for labels (`labels_dir` is required up front, there is no temp fallback: the CLI makes it, the shard scratch's `labels` directory or a lone process's own temp directory removed in its `finally`); (4) a process labels with ALL its workers (`[client, ...peers]`, Episodes spread over them, one at a time per worker, `activity.busy` held meanwhile) and so does the writer's recomputation, to the same bytes; a labeller error leaves `<hash>.search.error` (the error class) and the writer's 5% error names the first one. Tests: `packages/showdown-bridge/test/search-labeller-selection.test.ts` (hash vectors, type test), `packages/team-dataset/test/search-labels.test.ts` (real engine, belief and probe with the stand-in worker: determinism, the seed and run checks, every refusal reason, invariance to unrevealed opponent fields at equal player channels with the negative control of a belief given the true team, a feature pair, a generation whose PPO stream equals the unlabelled one and whose label stream and manifest are equal on a rerun, with one process and with two, scratch-file behaviour, the 5% rule, no label file when nothing is selected), `generation-cli.test.ts`, `packages/team-dataset/test/generation-cli-labels.test.ts` (the command end to end with the fake worker behind a wrapper script and `labels-shard-script.ts`: two game processes against a lone process with two workers give the same files, the games' own label files mean nothing is recomputed, scratch is removed, the counts print), `tests/ml/inspector/test_readers.py`, `tests/ml/loop/test_search_distill.py` (counts against files). The label streams read back through Python `check_stream_file`. Not run here: the real-worker tiny loop with kills at its stages (the driver side is `tests/ml/loop/test_search_distill.py`; a lost generation is replayed whole from its plan and the labels are a pure function of the Episodes), the per-label cost measurement (the machine is shared with a training run); both are open for SD-f (#1292), the pilot that measures cost.
